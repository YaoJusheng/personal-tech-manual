    一、目标与适用范围¶

    1.1 目标定义¶

    利用 AI 工具完成从 选题策划 -> 剧本创作 -> 分镜拆解 -> 角色/场景资产 -> 视频镜头生成 -> 配音配乐 -> 字幕剪辑 -> 发布复盘 的短视频生产流程，在不同预算下形成可执行、可复用、可扩展的内容生产方案。

    本文重点解决 4 个问题：

    1. 个人或小团队如何低成本跑通第一条 AI 短视频。
    2. 连载短剧/漫剧如何保证角色、画风、声音的一致性。
    3. 商业化项目如何选择 API、工具链和质检流程。
    4. 不同成本档位下，应该怎么取舍速度、质量、稳定性和版权风险。

    1.2 推荐产出形态¶

    类型 时长 特点 难度 推荐方案
    口播/资讯短视频 30-90 秒 旁白驱动，画面可用关键帧/素材 低 零成本流、极速流
    知识科普/带货种草 1-3 分钟 结构化脚本 + 产品图 + 字幕 中 标准 API 流
    AI 漫剧/动态漫 2-5 分钟/集 角色、场景、对白连续 中高 精品漫剧流
    AI 仿真人短剧 1-3 分钟/集 真人感、口型、动作要求高 高 商业质量流
    品牌广告/投放素材 15-60 秒 画质、版权、审核要求高 高 商业质量流

    1.3 核心指标¶

    指标 建议标准 说明
    单集成本 0-50 元、50-300 元、300-2000 元分档 按目标内容选择预算，不建议一开始重投入
    单集周期 1-4 小时、1-2 天、3-5 天分档 速度越快，越要牺牲复杂镜头和一致性
    角色一致性 同一角色脸型、发型、服饰、声线稳定 连载内容的关键门槛
    音画同步 旁白、字幕、画面节奏匹配 影响完播率和专业感
    可复用性 剧本模板、分镜模板、角色资产、音色资产可复用 决定能否批量生产
    合规性 音乐、字体、素材、音色、肖像授权清晰 商业化前必须确认

    二、总体技术架构¶

    2.1 最稳妥的生产链路¶

    当前更可靠的方案不是让一个模型端到端生成完整短片，而是采用“分段生成 + 统一合成 + 人工质检”的链路：

    选题/定位
  -> LLM 生成剧本与分镜 JSON
  -> 图像模型生成角色、场景、关键帧
  -> 视频模型按镜头生成 4-15 秒片段
  -> TTS 生成旁白/角色对白
  -> ASR/字幕工具生成字幕与时间轴
  -> BGM/音效补充氛围
  -> 剪映/Premiere/FFmpeg 合成输出
  -> 人工审核与平台发布
  -> 数据复盘反哺下一集

    这个链路的优点是：

    • 可控：每个镜头都能单独重生成，不会整片报废。
    • 可降本：重要镜头用高质量模型，过渡镜头用低成本模型。
    • 可扩展：后续能替换任一模型或平台，不被单一工具锁死。
    • 可审计：可以保存提示词、模型版本、输出时间和授权记录。

    2.2 自动化数据格式建议¶

    如果后续要做半自动或全自动工作流，建议让 LLM 输出结构化 JSON，而不是只输出自然语言剧本。

    {
  "title": "第1集：雨夜重逢",
  "duration_seconds": 90,
  "style": "都市甜宠，电影感，竖屏 9:16",
  "characters": [
    {
      "name": "林晓",
      "age": 25,
      "appearance": "短发，白色衬衫，浅色风衣",
      "voice": "年轻女性，克制但有情绪"
    }
  ],
  "shots": [
    {
      "shot_id": 1,
      "duration": 6,
      "scene": "雨夜写字楼门口",
      "camera": "中景，轻微推近",
      "visual_prompt": "cinematic rainy night, office entrance, young woman in white shirt...",
      "dialogue": "你怎么会在这里？",

    }

}

    2.3 关键原则¶

    1. 先分镜，后视频：直接文生视频容易漂移，先出关键帧再图生视频更稳定。
    2. 先固定资产，再批量生产：角色图、场景图、音色、字体、片头片尾应尽早沉淀。
    3. 先做短样片，再做连载：先用 1-3 条验证题材和工具链，再决定是否投入长篇。
    4. 先保证故事，再追求画质：短视频完播率更多由钩子、冲突、节奏决定。
    5. 先确认授权，再商业投放：音乐、音色、人物形象、字体和素材要留证。

    3.1.3 剧本输出要求¶

    AI 短视频剧本不能只写对白，必须包含画面可执行信息：

    • 强钩子：前 3 秒给出冲突、反差、悬念或利益点。
    • 镜头颗粒度：每 4-8 秒一个镜头，复杂短剧可 8-15 秒一个镜头。
    • 视觉描述：场景、光线、人物位置、服装、动作、景别。
    • 情绪标记：对白要标注愤怒、迟疑、压抑、温柔等情绪。
    • 字幕友好：句子短、信息密度高，避免长句堆叠。
    • 结尾动作：引导评论、关注、下一集悬念或购买转化。

    AI 漫剧剧本特殊性：

    • AI 短剧剧本需要详细场景描写（真人剧不需要形容词，AI 需要视觉描述来生成画面）
    • 建议每集 800-1500 字，包含场景描述、角色动作、对白和情绪标记
    • 剧本应标注镜头语言提示（特写、中景、远景），便于后续分镜环节使用

  -> 图像 API 生成关键帧
  -> 视频 API 生成镜头片段

    LLM 服务

  -> Whisper/faster-whisper 字幕
  -> 开源或企业 TTS
  -> FFmpeg 合成
  -> 任务队列 + 对象存储 + 审核系统

    优点：成本可控、数据可私有化、可深度定制。
    缺点：显卡、部署、调参、运维成本高，效果需要持续打磨。
    适合：技术团队、稳定题材、规模化生产、企业私有内容。

    五、OpenMontage 视频方案¶

    OpenMontage 更适合作为 AI 视频生产编排层，放在“脚本/分镜生成之后、最终剪辑出片之前”。它不是单一视频模型，而是把脚本理解、素材生成、模型路由、配音字幕、渲染合成、质量检查和失败恢复串成一条可配置流水线。

    对短视频和 AI 漫剧来说，OpenMontage 的价值主要体现在 4 点：

    1. 流程标准化：用 pipeline 定义每个阶段的输入、输出、工具和质检门槛。
    2. 模型可替换：图像、视频、TTS、字幕、渲染器都可以按成本和质量切换 provider。
    3. 失败可恢复：长任务可以通过 checkpoint/resume 避免整条链路重跑。
    4. 适合工程化：比手工工具链更容易沉淀为团队后台、批量任务和自动化生产系统。

    5.1 定位、适用场景与放置位置¶

    OpenMontage 适合承接这些内容类型：

    场景 适配方式 说明
    口播/解说短视频 animated-explainer、talking-head 脚本、素材、配音、字幕和合成自动化程度高
    短剧/AI 漫剧 character-animation、cinematic 需要角色参考、镜头表、视频生成和后期质检
    数字人/虚拟主播 avatar-spokesperson 适合口播、课程、产品介绍、企业宣传
    素材混剪 clip-factory、hybrid 可组合 stock 素材、AI 生成素材和已有视频
    本地化配音 localization-dub 适合出海短视频、多语言重配音和字幕改写
    屏幕演示 screen-demo 适合软件教程、工具演示和产品 walkthrough

    推荐链路：

    LLM 生成剧本/分镜 JSON

    5.3.4 Pipeline 配置示例¶

    下面是适合 60-90 秒 AI 漫剧样片的简化配置思路，实际字段应以仓库当前 pipeline_defs/*.yaml 为准：

    id: ai_micro_drama_vertical
aspect_ratio: "9:16"
resolution: "1080x1920"
render_runtime: ffmpeg

stages:
  - id: script
    input: brief.md
    output: script.json
    quality_gate: human_review

  - id: scene_plan
    input: script.json
    output: shots.json
    require_fields: [shot_id, duration, characters, visual_prompt, dialogue, sfx]

  - id: assets
    providers:
      image: flux_or_local_diffusion
      video: kling_or_wan_fallback
      tts: elevenlabs_or_piper
    checkpoint: true

  - id: compose
    renderer: ffmpeg
    validate: [subtitle_present, audio_levels, no_black_frames]

    配置原则：render_runtime 应在 proposal 阶段确定并锁定；知识解释类优先 Remotion，强动效包装类优先 HyperFrames，普通短剧拼接和字幕压制优先 FFmpeg。渲染器中途静默替换会影响质检标准和可复现性，不建议允许。

    5.4 模型与工具组合选择¶

    5.4.1 模型选择¶

    OpenMontage 的关键不是固定某一个模型，而是为每个环节建立“首选 + 备选 + 降级”的组合。

    环节 云端高质量 低成本/本地 适合策略
    LLM 脚本/分镜 OpenAI、Claude、Gemini、通义、DeepSeek Qwen、Llama、DeepSeek 开源模型 中文短剧优先 DeepSeek/通义，复杂结构用高端 LLM 复核
    图像/关键帧 FLUX、Google Imagen、DALL-E 3、Recraft、Grok Imagine Image Stable Diffusion/Local Diffusion 角色定稿用高质量模型，普通背景可用本地或低价模型
    视频生成 Kling、Runway Gen-4、Google Veo 3、MiniMax、Higgsfield、HeyGen WAN 2.1、Hunyuan、CogVideo、LTX-Video 关键剧情镜头用云端高质量，过渡镜头用本地或低价 provider
    素材补充 Pexels、Pixabay、Wikimedia Commons、Unsplash 自建素材库 空镜、转场、环境镜头优先用 stock 降低成本
    TTS 配音 ElevenLabs、OpenAI TTS、Google TTS Piper 商业项目用授权清晰的云端 TTS，样片可用 Piper 降本
    字幕/转写 Whisper API、平台 ASR Whisper/faster-whisper 先生成最终配音，再转写出字幕时间轴
    合成后期 云端剪辑服务 FFmpeg、Remotion、HyperFrames 标准化批量合成优先本地，创意动效按渲染器选择

    推荐组合：

    目标 推荐组合 说明
    低成本口播短视频 DeepSeek + stock 素材 + Piper/Edge TTS + FFmpeg 重点验证内容结构和发布数据
    知识科普/解释类视频 LLM 分镜 + 图像模型 + Remotion + TTS + 字幕 Remotion 更适合数据驱动、React scene stack 和 explainers
    AI 漫剧样片 DeepSeek/Claude + FLUX/SDXL + Kling/WAN + ElevenLabs + FFmpeg 先做角色卡和关键帧，再图生视频
    动效广告/包装短片 高质量 LLM + Imagen/FLUX + HyperFrames + 专业 TTS HyperFrames 更适合 HTML + GSAP 和 motion-graphics-heavy brief
    数字人口播 LLM 脚本 + HeyGen/Avatar/Lip-sync + TTS + 字幕 适合课程、企业介绍、产品讲解

    5.4.2 零 Key 模式下的工具链¶

    执行完 make setup 之后，即使完全不填任何 API Key，你也可以直接开始做视频。这套开箱即用的免费工具链包含以下几块：

    • 旁白合成：Piper TTS。这是一个 C++ 写的高质量离线文本转语音引擎，源自 Rhasspy 项目，支持中英日法等数十种语言，MOS 评分在开源 TTS 里属于第一梯队。完全跑在本机 CPU 上，不联网、不上传、无配额。
    • 画面素材：Pexels 和 Pixabay。两家都是全球知名的免费商用素材站，API Key 可以免费申请。
    • Pexels 覆盖大量人物、风景、城市、职场类短镜头；
    • Pixabay 则在卡通、图形、矢量素材方面更强。两个加起来足以覆盖绝大多数通用场景。
    • 档案素材：Archive.org 互联网档案馆、NASA 公开图库、Wikimedia Commons。这三家是"真实素材纪录片路线"的主力。Archive.org 藏着海量公共领域老电影、纪录片、新闻影像；NASA 图库里有所有公开的太空、行星、地球科学影像；Wikimedia Commons 里则是自然、动物、建筑、历史文物的金矿。三家全部是公共领域或开放许可，合规使用无压力。
    • 视频合成引擎：Remotion。这是基于 React 的"程序化视频"框架，也是 OpenMontage 最核心的底座之一。它能把一堆静态图片"动起来"：加弹簧物理动画、做画面切换、叠加排版精致的字幕、做 TikTok 风格的逐词高亮字幕、加入 Google Fonts 的字体、处理音频淡入淡出曲线。关键在于它所有效果都是 React 代码写出来的——也就是说，AI 编程助手对它的驾驭能力几乎是天生的。
    • 后期处理：FFmpeg。视频工业的瑞士军刀。编码、切片、字幕烧录、音轨混合、调色、变速、转码、抽帧，全能搞定。命令行工具，本机免费。
    • 字幕生成：内置 WhisperX 集成。做自动逐词时间轴字幕，精度达到"每个词单独高亮"的级别，直接支持 SRT 和 VTT 两种格式。

    参考：OpenMontage拆解

    5.5 Pipeline 执行流程与质量门槛¶

    OpenMontage 的标准执行逻辑不是“一次提示词直接出片”，而是分阶段推进：

    research
  -> proposal
  -> script
  -> scene_plan
  -> assets
  -> edit
  -> compose
  -> post_render_review
    阶段 关键产物 质量门槛
    research 题材、竞品、平台约束、素材来源 不使用不可商用素材，不直接模仿特定 IP
    proposal pipeline、provider、预算、画幅、渲染器 人工确认目标、预算和 render_runtime
    script 剧本、对白、旁白、字幕草稿 前 3 秒钩子、转折、结尾动作清晰
    scene_plan 分镜表、镜头时长、提示词、音效点 每个镜头可独立生成、重试和替换
    assets 角色图、关键帧、视频片段、音频、BGM 角色一致性、画面无明显畸形、音色统一
    edit 镜头排序、字幕、音频混合、转场 音画节奏匹配，字幕不遮挡关键主体
    compose 初版成片、项目记录 FFmpeg/Remotion/HyperFrames 输出参数正确
    post_render_review 质检报告、返工清单 检查黑帧、音量、字幕、交付承诺和版权记录

    建议强制设置 5 个确认点：proposal、script、scene_plan、generated assets、publish。这样能把大部分返工控制在低成本阶段，而不是最后成片后整体推倒重做。

    5.6 AI 漫剧专用配置建议¶

    AI 漫剧比普通短视频更依赖角色一致性和连续镜头，建议为每个项目单独维护一套 pipeline。

    模块 配置重点 质检标准
    角色卡 外貌、服装、发型、表情、禁用变化项、参考图 同一角色跨镜头脸型和服装稳定
    场景库 固定地点、色调、光线、镜头语言 同一场景不要频繁改变空间结构
    分镜 JSON 镜头编号、时长、景别、角色、动作、对白、情绪 每个镜头都能独立生成和重试
    视频 provider 关键镜头、普通镜头、失败降级策略 单镜头最多重试次数和成本上限明确
    口型与对白 正脸对白、侧脸对白、旁白、反应镜头分层 口型不稳时用侧脸/背影/反应镜头规避
    质检门槛 pre-compose、post-render、人工复核 检查角色漂移、字幕、音画同步、畸形画面

    AI 漫剧推荐先把镜头分成 3 类：

    1. 剧情关键镜头：决定情绪和转折，使用高质量图像/视频模型，多给重试预算。
    2. 对白承接镜头：优先使用半身、侧脸、反应镜头，降低口型压力。
    3. 过渡氛围镜头：街景、房间、道具、天空、手部动作等，可用 stock 或低成本模型。

    5.7 从 PoC 到生产的落地步骤¶

    阶段 1：PoC 跑通闭环¶

    1. 选择最小 pipeline：先选 animated-explainer、talking-head 或单一短剧样片，不要一开始做完整连载。
    2. 准备输入：提供创作目标、平台、时长、画幅、角色卡、分镜 JSON、配音风格和字幕样式。
    3. 接入一套云端模型：先用稳定 provider 跑通 LLM、图像/视频、TTS、字幕、合成。
    4. 验证渲染器：知识解释类优先 Remotion，重动效包装类优先 HyperFrames，普通拼接合成可用 FFmpeg。
    5. 输出样片：只追求流程可用，记录失败镜头、耗时、成本和人工介入点。

    阶段 2：小规模试运行¶

    1. 固化 stage 输入输出：每个阶段都保存 JSON、提示词、模型版本、素材路径和输出文件。
    2. 配置 provider 回退：云端失败时切换本地视频、stock 素材或静帧动画，不让任务直接中断。
    3. 增加 quality gates：至少包含脚本审查、pre-compose validation、post-render self-review。
    4. 建立资产库：保存角色图、场景图、音色、BGM、字幕样式、片头片尾。
    5. 统计成本与失败率：按镜头记录生成次数、单镜头成本、失败原因和可复用素材。

    阶段 3：生产化¶

    1. 固化 pipeline 配置：把短视频、漫剧、数字人、混剪分别做成独立 pipeline_defs/*.yaml。
    2. 建立 provider 白名单：按质量、成本、速度、授权风险给 LLM、图像、视频、TTS 分级。
    3. 启用 checkpoint/resume：保证长任务失败后能从最近阶段恢复。
    4. 加入人工审核节点：商业化前必须检查事实、版权、敏感内容、角色一致性和音画同步。
    5. 接入监控和成本看板：按项目、集数、镜头、模型统计耗时、费用、失败率和返工率。

    5.8 风险与限制¶

    • 不是端到端魔法工具：OpenMontage 的质量取决于 pipeline 设计、stage director skills 和接入 provider 的能力。
    • 本地视频生成有 GPU 门槛：低显存只能选择轻量模型，高质量生成通常需要更高 VRAM 和更长时间。
    • 供应商不稳定：云端视频模型可能遇到排队、限额、价格、审核策略和 API 变更。
    • AI 漫剧仍需人工质检：强角色一致性、连续动作、口型同步很难完全自动化。
    • 渲染器不能乱选：Remotion 更适合数据/组件化 explainers，HyperFrames 更适合强动效包装，普通视频拼接优先 FFmpeg。
    • 商业化要留证：模型版本、提示词、素材来源、音色授权、字体和音乐授权都要可追溯。

    六、按成本档位的完整方案¶

    6.1 方案 A：零成本入门流（0 元/条，2-4 小时）¶

    适合：个人练手、概念验证、学习流程、账号试水。
    目标：不用本地 GPU，不购买订阅，完成一条可发布的 30-90 秒短视频。

    工具组合¶

    环节 推荐工具 说明
    选题/剧本 DeepSeek、Kimi、豆包 生成口播稿和分镜
    角色/画面 即梦、通义万相、可灵免费额度 生成关键帧或短视频片段
    配音 Edge TTS、TTSMaker、剪映配音 免费或免费额度
    字幕 剪映自动字幕 快速生成和修正
    BGM/音效 剪映素材库、免费音乐库 注意授权说明
    剪辑 剪映专业版 免费完成合成

    流程步骤¶

    1. 确定题材：选择一个足够简单的内容，例如热点吐槽、职场故事、知识科普。
    2. 生成脚本：让 LLM 输出 30-90 秒脚本，要求前 3 秒钩子、3-6 个镜头、结尾互动。
    3. 拆分镜头：把脚本拆成 4-8 个镜头，每个镜头写清画面提示词。
    4. 生成关键帧：每个镜头生成 1 张图，优先保证风格一致。
    5. 生成动态片段：用免费额度做简单推拉、人物微动或环境动态。
    6. 生成配音：用 Edge TTS/TTSMaker/剪映配音输出旁白。
    7. 剪辑合成：导入剪映，按旁白节奏排画面，加字幕、BGM、转场。
    8. 人工质检：检查错字、人物变形、音量、字幕遮挡、平台敏感内容。
    9. 发布复盘：记录标题、封面、完播率、评论反馈，作为下一条输入。

    成本与效果¶

    项目 成本
    LLM 免费
    图片/视频 免费额度
    配音/字幕 免费
    剪辑 免费
    合计 0 元，主要成本是时间

    优点：门槛最低，适合快速理解全流程。
    缺点：免费额度不稳定，画质和一致性有限，不适合一开始做复杂短剧。

    6.2 方案 B：极速日更流（15-80 元/条，1-2 小时）¶

    适合：资讯吐槽、热点追风、矩阵号、知识科普、轻带货。
    目标：低成本高频发布，重点追求速度和稳定出片。

    工具组合¶

    环节 推荐工具 取舍
    剧本 DeepSeek/Kimi/通义千问 低成本中文脚本
    图片 Midjourney/即梦/通义万相 快速生成封面和关键帧
    视频 可灵/即梦/PixVerse/Runway 图生视频，控制成本
    配音 MiniMax/火山 TTS/剪映 提升自然度
    BGM Suno/剪映音效库 重要内容可定制 BGM
    剪辑 剪映模板 固定模板提高效率

    标准流程¶

    0-10 分钟：确定选题，抓取热点或商品卖点
10-25 分钟：LLM 生成脚本、标题、封面文案、分镜表
25-45 分钟：生成 5-8 张关键帧或素材图
45-70 分钟：将关键帧转成 4-8 个视频片段
70-85 分钟：生成配音、字幕和 BGM
85-110 分钟：剪映套模板，调整节奏，导出
110-120 分钟：检查并发布

    成本估算¶

    项目 费用
    剧本 0-5 元
    图片生成 3-15 元
    视频生成 10-50 元
    配音 0-10 元
    BGM/音效 0-10 元
    合计 15-80 元/条

    操作要点¶

    • 固定栏目模板，例如“3 个反常识知识点”“今天的职场离谱瞬间”。
    • 固定片头、片尾、字幕样式和 BGM 风格。
    • 不追求每个镜头复杂运动，优先保证节奏和信息密度。
    • 每天保留数据表：选题、标题、封面、发布时间、完播率、互动率。

    6.3 方案 C：标准 API 生产流（80-500 元/条，0.5-1 天）¶

    适合：内容团队、广告素材、带货短视频、企业宣传、稳定栏目。
    目标：在质量、效率、可控性之间取得平衡。

    推荐架构¶

    运营输入：主题/商品/目标人群/平台
  -> LLM API 生成脚本 + 分镜 JSON
  -> 图像 API 批量生成关键帧
  -> 视频 API 异步生成镜头
  -> TTS API 生成旁白/对白
  -> ASR/字幕服务生成字幕
  -> FFmpeg/剪辑工具合成
  -> 人工审核

    流程步骤¶

    1. 建立模板库：为每个栏目固定脚本结构、镜头数量、字幕样式、片尾 CTA。
    2. 建立资产库：保存商品图、角色图、品牌色、LOGO、BGM、常用音效。
    3. 脚本结构化：LLM 输出 JSON，字段包含镜头、提示词、旁白、字幕、音效点。
    4. 批量生成关键帧：每个镜头至少生成 2 个候选图，人工选择最优。
    5. 异步生成视频：视频生成通常耗时较长，建议队列化并允许失败重试。
    6. 生成音频字幕：TTS 先出最终音频，再根据音频生成字幕时间轴。
    7. 自动合成初稿：用 FFmpeg 或剪辑模板生成初稿。
    8. 人工复核：重点查事实错误、商品表达、版权、人物变形、字幕错字。
    9. 多版本输出：同一素材输出 2-3 个标题/封面/开头版本做 A/B 测试。

    成本估算¶

    项目 费用
    LLM API 1-20 元
    图片生成 10-50 元
    视频生成 50-300 元
    TTS/字幕 5-50 元
    后期和人工 20-100 元
    合计 80-500 元/条

    优缺点¶

    • 优点：可标准化、可批量、质量较稳定，适合团队协作。
    • 缺点：需要一定工程能力，供应商接口和价格可能变化。

    6.4 方案 D：精品漫剧/连载 IP 流（500-2000 元/集，3-5 天）¶

    适合：AI 漫剧、动态漫、连载短剧、出海内容、IP 孵化。
    目标：保证人物、画风、剧情、声音的连续性。

    前置资产建设¶

    资产 内容 建议
    世界观文档 背景、规则、时间线、核心冲突 用表格或知识库维护
    角色卡 外貌、性格、关系、口头禅、禁忌变化 每个主角单独建档
    视觉风格板 色调、画风、镜头语言、参考作品 避免直接仿冒特定 IP
    场景库 家、公司、街道、学校等固定场景 减少每集重复生成成本
    声音库 每个角色的音色、语速、情绪范围 商用前确认授权
    分镜模板 常用景别、转场、情绪镜头 提升连载效率

    生产流程¶

    第 0 阶段：角色和世界观设定（一次性，3-7 天）
  -> 主角设定、视觉风格板、LoRA/参考图、声线档案

第 1 阶段：单集剧本（0.5-1 天）
  -> 大纲、冲突、对白、悬念、分镜 JSON

第 2 阶段：分镜和关键帧（1-2 天）
  -> 每集 10-25 个镜头，先出关键帧，统一画风

第 3 阶段：视频生成（0.5-1 天）
  -> 重点镜头用高质量模型，普通镜头用低成本模型

第 4 阶段：音频后期（0.5 天）
  -> 角色 TTS、BGM、环境音、字幕

第 5 阶段：剪辑质检（0.5 天）
  -> 节奏、错字、角色漂移、服装变化、音画同步

    成本估算¶

    项目 费用
    角色/场景资产摊销 50-300 元/集
    图片和关键帧 50-200 元/集
    视频生成 200-1000 元/集
    配音/BGM/音效 50-300 元/集
    人工后期 150-500 元/集
    合计 500-2000 元/集

    质量控制重点¶

    • 主角每集服装、发型、脸型是否稳定。
    • 分镜是否真的服务剧情，而不是炫技堆画面。
    • 每集是否有明确爽点、冲突和结尾悬念。
    • 口型不佳时，不要强行做正脸对白，可用背影、侧脸、反应镜头规避。

    6.5 方案 E：商业质量流（2000 元以上/条，3-10 天）¶

    适合：品牌广告、投放素材、课程宣传、商业短片、虚拟代言。
    目标：可交付、可审查、可复用，重视版权和品牌安全。

    推荐流程¶

    1. 需求确认：目标人群、投放平台、品牌调性、禁用词、竞品边界。
    2. 创意脚本：至少 3 个创意方向，人工评审后选 1 个主方案。
    3. 视觉提案：风格板、角色设定、分镜脚本、封面方向。
    4. 资产授权检查：字体、音乐、音色、参考图、真人肖像全部留证。
    5. 高质量镜头生成：重要镜头使用高端商业模型，多轮重生成。
    6. 专业后期：调色、混音、字幕、LOGO、包装、法务审核。
    7. 多版本交付：15 秒、30 秒、60 秒；横版、竖版；不同开头版本。
    8. 投放复盘：根据 CTR、CVR、完播率调整下一批素材。

    成本结构¶

    项目 说明
    创意策划 人工成本高于模型成本
    高质量视频生成 重点镜头反复生成，成本上升明显
    专业配音/音乐 商用授权和音色授权必须确认
    后期包装 调色、混音、动效、字幕、版本适配
    审核合规 品牌、法务、平台投放审核

    七、标准 SOP：以 90 秒短剧为例¶

    7.1 制作规格¶

    项目 建议
    时长 60-90 秒
    镜头数 8-15 个
    单镜头时长 4-8 秒为主
    画幅 9:16，1080x1920
    字幕 每行不超过 14-18 个中文字符
    开头 3 秒内出现冲突或反差
    结尾 悬念、反转、评论引导或转化 CTA

    7.2 详细步骤¶

    1. 选题：明确题材、受众、平台和目标指标。
    2. 写一句话梗概：主角是谁，遇到什么冲突，结果有什么反转。
    3. 生成剧本：让 LLM 输出脚本、分镜表和 JSON。
    4. 人工审稿：删掉无效铺垫，强化前 3 秒和结尾悬念。
    5. 创建角色卡：确认角色外观、服装、声音、禁用变化项。
    6. 生成风格板：先出 3-5 张统一风格参考图。
    7. 生成关键帧：每个镜头 1-3 张候选图，选最稳定的一张。
    8. 生成视频片段：关键帧转视频，失败镜头只重做该镜头。
    9. 生成配音：按角色和情绪生成音频，统一响度。
    10. 生成字幕：用 ASR 或剪映生成字幕，人工修正断句。
    11. 剪辑合成：按配音节奏排镜头，补 BGM、音效、转场。
    12. 质检导出：检查画面、声音、字幕、版权和平台规则。
    13. 发布测试：至少测试 2 个标题/封面版本。
    14. 复盘迭代：记录完播率、互动率、转粉率，调整下一集。

    7.3 质检清单¶

    检查项 标准
    剧情 3 秒有钩子，15-20 秒有转折，结尾有动作
    角色 脸、发型、服装、配饰不漂移
    画面 无明显畸形手、错脸、穿模、文字乱码
    音频 人声清晰，BGM 不压人声，无突兀爆音
    字幕 无错字，断句自然，不遮挡关键画面
    版权 音乐、字体、素材、音色授权可追溯
    平台 无敏感词、违规画面、虚假宣传

    八、常见问题与避坑指南¶

    8.1 角色漂移¶

    表现：同一角色脸变了、衣服变了、发型变了。
    解决：

    • 每个镜头都带角色参考图。
    • 提示词固定“不可变化项”。
    • 连载项目使用 LoRA、IP-Adapter 或平台角色档案。
    • 减少同一集中不必要的换装和复杂动作。

    8.2 口型不准¶

    表现：说话时嘴型和音频不匹配。
    解决：

    • 低成本方案减少正脸长对白，多用旁白、侧脸、背影、反应镜头。
    • 重要对白单独使用口型同步工具或支持 lip-sync 的平台。
    • 先配音，再根据音频节奏剪辑画面。

    8.3 视频生成失败率高¶

    表现：手部畸形、人物乱动、镜头不听指令。
    解决：

    • 镜头动作越简单越稳定，优先使用推近、轻微摇镜、环境运动。
    • 复杂打斗、舞蹈、多人互动要拆成多个短镜头。
    • 重要镜头准备首尾帧，提高运动方向可控性。

    8.4 成本失控¶

    表现：一个镜头反复生成几十次，单集成本超预算。
    解决：

    • 先定每集最大镜头数和每镜头最大重试次数。
    • 只对关键镜头使用高价模型。
    • 建立素材库复用背景、转场、空镜、反应镜头。
    • 先上线测试数据，再决定是否提高制作规格。

    8.5 版权和合规风险¶

    重点风险：

    • 未授权使用真人肖像或声音克隆。
    • 使用不明确可商用的 BGM、字体、图片素材。
    • 模仿知名 IP、明星、品牌形象。
    • 广告/带货中出现夸大宣传或不可验证承诺。

    建议做法：

    • 保存提示词、模型、时间、素材来源、授权截图。
    • 商业项目使用版权音乐库和企业级 TTS。
    • 克隆音色、真人形象、品牌露出必须取得书面授权。
    • 发布前做敏感词、事实、版权三类审核。

    你的情况 推荐

    9.3 推荐起步路径¶

    1. 第 1 周：用零成本工具跑通 3 条 30-60 秒视频。
    2. 第 2 周：选择数据最好的一类题材，固定脚本和剪辑模板。
    3. 第 3-4 周：引入付费图生视频和更好的 TTS，提高稳定性。
    4. 第 2 个月：建立角色/场景/音效/封面资产库。
    5. 第 3 个月：如果数据成立，再考虑 API 自动化或精品连载。

    十、最终结论¶

    1. 最推荐的总架构：LLM 剧本/分镜 -> 图像关键帧 -> 图生视频 -> TTS 配音 -> ASR 字幕 -> 剪辑/FFmpeg 合成 -> 人工审核 -> 发布复盘。
    2. 新手不要追求一步到位：先用免费工具跑通闭环，再根据数据决定是否升级模型和预算。
    3. 商业化不要完全依赖黑盒平台：脚本、分镜、资产、授权和质检记录必须自己掌握。
    4. 角色一致性是连载内容的核心壁垒：角色卡、参考图、LoRA/角色档案、分镜质检比单纯换模型更重要。
    5. 故事和节奏仍然是第一生产力：AI 降低了制作门槛，但没有降低内容竞争门槛。真正影响完播和转化的是选题、钩子、冲突、节奏和复盘能力。
