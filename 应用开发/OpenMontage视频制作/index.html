    一、目标与总体思路¶

    如果已经有一个剧本，使用 OpenMontage 制作 AI 短剧时，不建议把剧本直接交给视频模型生成完整成片。更稳妥的做法是把剧本拆成 角色资产、场景资产、视觉风格、分镜镜头、音频字幕和渲染配置，再由 OpenMontage 按 pipeline 分阶段执行、质检、返工和合成。

    OpenMontage 在这个流程里主要承担 4 个角色：

    1. 编排层：让每个阶段都有明确输入、输出、工具和质量门槛。
    2. 模型路由层：中等质量用低成本模型，高质量镜头切换更强 provider。
    3. 可恢复执行层：通过 checkpoint 保存中间结果，失败后只重跑某个阶段或镜头。
    4. 可复现生产层：保存提示词、模型、素材来源、成本和输出记录，方便批量生产。

    完整链路如下：

    已有剧本
  -> 剧本清洗与结构化
  -> 导入 OpenMontage 项目
  -> 选择短剧 pipeline
  -> 准备角色卡/场景卡/视觉风格板
  -> 生成分镜 JSON / shots.json
  -> 生成角色与场景关键帧
  -> 图生视频生成每个镜头
  -> 生成角色对白/旁白/BGM/音效
  -> 生成字幕时间轴
  -> OpenMontage 编排 edit/compose
  -> pre-compose 质检
  -> 渲染成片
  -> post-render 质检
  -> 人工返工与最终导出

    二、环境准备¶

    2.1 安装 OpenMontage¶

    git clone https://github.com/calesthio/OpenMontage.git
cd OpenMontage
make setup

    基础依赖：

    python3 --version    # 3.10+
node --version       # 18+
ffmpeg -version

    如果没有 make，可以手动安装：

    python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cd remotion-composer && npm install && cd ..
python -m pip install piper-tts
cp .env.example .env

    Windows PowerShell 可参考：

    py -3 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
cd remotion-composer; npm install; cd ..
python -m pip install piper-tts
Copy-Item .env.example .env

    2.2 配置 .env¶

    中等质量建议先配置：

    FAL_KEY=your-fal-key
PEXELS_API_KEY=your-key
PIXABAY_API_KEY=your-key
OPENAI_API_KEY=your-key
ELEVENLABS_API_KEY=your-key

    高质量建议增加：

    RUNWAY_API_KEY=your-key
HEYGEN_API_KEY=your-key
GOOGLE_API_KEY=your-key
UNSPLASH_ACCESS_KEY=your-key

    如果有本地 GPU，可开启本地视频生成：

    make install-gpu

VIDEO_GEN_LOCAL_ENABLED=true
VIDEO_GEN_LOCAL_MODEL=wan2.1-1.3b

    可选本地模型通常包括：wan2.1-1.3b、wan2.1-14b、hunyuan-1.5、ltx2-local、cogvideo-5b。

    2.3 检查可用能力¶

    python -c "from tools.tool_registry import registry; import json; registry.discover(); print(json.dumps(registry.support_envelope(), indent=2))"
python -c "from tools.tool_registry import registry; import json; registry.discover(); print(json.dumps(registry.provider_menu(), indent=2))"

    三、通过 IDE/AI 编程助手调用 OpenMontage¶

    OpenMontage 更适合被 Codex、Claude Code、OpenCode、Copilot 这类 IDE/CLI AI 编程助手作为“视频生产项目仓库”来调用，而不是当作单一按钮式视频生成工具。推荐让 AI 助手先读取仓库指令，再按 pipeline 分阶段生成项目文件、分镜、素材、音频、字幕和合成产物。

    核心调用关系如下：

    AI 编程助手
  -> 读取 AGENT_GUIDE.md / PROJECT_CONTEXT.md / pipeline_defs
  -> 理解剧本、预算、画幅、质量档位和输出目标
  -> 检查 tools/tool_registry 与 provider_menu
  -> 选择或定制 pipeline
  -> 分阶段生成 shots.json、关键帧、视频片段、音频、字幕、合成配置
  -> 调用图像/视频/TTS/音乐/FFmpeg/Remotion 等工具
  -> 输出 draft/final 视频、qc_report.md、cost_report.json、asset_manifest.json

    3.1 通用使用流程¶

    无论使用哪一种 AI 编程助手，都建议按以下顺序落地：

    1. 打开 OpenMontage 仓库：在 IDE 或终端中进入 OpenMontage 根目录，确保助手能读取整个工作区。
    2. 先读项目指令：要求助手阅读 AGENT_GUIDE.md、PROJECT_CONTEXT.md、docs/PROVIDERS.md、pipeline_defs/。
    3. 执行能力预检：运行 provider_menu 和 support_envelope，确认图像、视频、TTS、音乐、字幕、合成 provider 是否可用。
    4. 创建生产项目：在 projects/<project_id>/ 下生成 brief.md、script.md、characters.yaml、scenes.yaml、style.md、budget.yaml。
    5. 先分镜再生成：输出 shots.json、production_plan.json、risk_shots.json，人工确认后再进入素材阶段。
    6. 分阶段确认：至少在 proposal、scene_plan、keyframes/assets、compose/publish 节点等待人工确认。
    7. 按镜头重跑：失败时只重跑对应 shot，不覆盖已确认素材，并记录 prompt、provider、成本和素材来源。

    可直接给任意助手的通用提示词：

    你现在在 OpenMontage 仓库中工作。请先阅读 AGENT_GUIDE.md、PROJECT_CONTEXT.md、docs/PROVIDERS.md 和 pipeline_defs/，再执行 provider menu 检查。

目标：基于 projects/<project_id>/script.md 制作一条 90 秒 9:16 AI 短剧，输出 1080x1920 mp4。

要求：
1. 先选择 cinematic、character-animation 或 hybrid pipeline，并输出 proposal，不要立即生成素材。
2. 将剧本拆成 shots.json，每个镜头包含 shot_id、duration、scene_id、characters、camera、action、dialogue、emotion、visual_prompt、negative_prompt、audio、quality_tier。
3. 先生成角色资产、场景资产和关键帧，人工确认后再图生视频。
4. 按 hero/dialogue/utility 镜头分层选择 provider，失败镜头只重跑对应 shot。
5. 生成 TTS、BGM、SFX、字幕、edit_decision.json，并用 FFmpeg/Remotion 合成 draft。
6. 输出 outputs/draft_v1.mp4、qc_report_v1.md、cost_report.json、asset_manifest.json。

    3.2 Codex：工程执行与自动化生产¶

    Codex 适合承担文件创建、命令执行、脚本调用、FFmpeg 合成、失败重试等工程执行工作。推荐流程：

    cd OpenMontage
codex

    启动提示词：

    请作为 OpenMontage 视频生产执行 agent 工作。先阅读 CODEX.md（如果存在）、AGENT_GUIDE.md、PROJECT_CONTEXT.md 和 docs/PROVIDERS.md，然后运行 provider menu 检查。
我的目标是基于 projects/<project_id>/script.md 制作 90 秒竖屏 AI 短剧。请先输出 pipeline proposal、预算、provider 路由和确认节点，不要开始生成素材。

    Codex 最适合执行：

    • 创建 projects/<project_id>/ 标准目录和 YAML/JSON 文件。
    • 生成和维护 shots.json、edit_decision.json、asset_manifest.json。
    • 调用图像、视频、TTS、字幕、FFmpeg/Remotion 等脚本。
    • 将失败镜头写入 failed_shots.json，只重跑失败 shot。
    • 修复 pipeline、provider、Python/Node/FFmpeg 脚本错误。

    3.3 Claude Code：导演分析与高质量分镜¶

    Claude Code 更适合做导演型工作：剧本理解、情绪曲线、镜头策略、风险镜头规避、高质量提示词和长流程规划。推荐流程：

    cd OpenMontage
claude

    启动提示词：

    请作为 OpenMontage 导演型 agent 工作。先阅读 CLAUDE.md（如果存在）、AGENT_GUIDE.md、PROJECT_CONTEXT.md、pipeline_defs/ 和 docs/PROVIDERS.md。
请分析 projects/<project_id>/script.md，输出 director_plan.md、推荐 pipeline、镜头策略、风险镜头、高质量制作方案和人工确认节点。只到 proposal 和 scene_plan 阶段，不要生成素材。

    建议让 Claude Code 输出：

    • director_plan.md：故事冲突、角色关系、情绪曲线、90 秒节奏表。
    • shots.json：包含 quality_tier、generation_strategy、risk_level、fallback_plan。
    • risk_shots.json：正脸长对白、复杂动作、多人互动、难生成特效等风险镜头。
    • production_plan.json：镜头级 provider 路由、预算估计、重试次数和人工确认点。

    3.4 OpenCode：工作流编排与团队 SOP¶

    OpenCode 适合把 OpenMontage 固化为团队工作流，结合自定义 agent、skill、MCP、权限和项目规则进行分阶段生产。推荐流程：

    cd OpenMontage
opencode

    如果仓库没有 OPENCODE.md，可新增轻量规则：

    # OPENCODE.md

Before any OpenMontage video production task:
1. Read AGENT_GUIDE.md and PROJECT_CONTEXT.md.
2. Inspect pipeline_defs/ and tools/tool_registry.
3. Run provider_menu before planning.
4. Save all outputs under projects/<project_id>/.
5. Ask for approval before generation-heavy stages.
6. Never overwrite confirmed assets without explicit approval.

    OpenCode 的推荐阶段指令：

    执行 stage: script_to_shots，输入 script.md、characters.yaml、scenes.yaml、style.md，输出 shots.json、risk_shots.json，完成后不要继续。

执行 stage: keyframes，输入 shots.json 和 references/，输出 assets/keyframes/、keyframe_review.md，只生成关键帧。

执行 stage: clips，输入已确认 keyframes，输出 assets/clips/、asset_manifest.json、failed_shots.json，按 quality_tier 路由 provider。

执行 stage: compose，输入 clips、dialogue、bgm、sfx、subtitles，输出 outputs/draft_v1.mp4、qc_report_v1.md。

    3.5 Copilot：IDE 辅助与脚本开发¶

    Copilot 适合在 VS Code 中辅助整理项目文件、修改 YAML/JSON、编写校验脚本和 FFmpeg 脚本。它可以参与完整流程，但更建议拆成小任务使用。

    建议在 .github/copilot-instructions.md 中加入：

    # Copilot Instructions for OpenMontage

When assisting with OpenMontage video production:
1. Read AGENT_GUIDE.md and PROJECT_CONTEXT.md before planning.
2. Use pipeline_defs/*.yaml to select a pipeline.
3. Use tools/tool_registry to understand available providers.
4. Keep all project outputs under projects/<project_id>/.
5. Use staged execution: proposal -> scene_plan -> keyframes -> clips -> audio -> subtitles -> edit -> compose -> qc.
6. Ask for confirmation before expensive generation stages.
7. Preserve prompt, provider, cost and source metadata.

    Copilot Chat 可用提示词：

    @workspace 请阅读 AGENT_GUIDE.md、PROJECT_CONTEXT.md、pipeline_defs/ 和 docs/PROVIDERS.md，帮我把 projects/<project_id>/script.md 整理成 OpenMontage 可执行项目。先生成 brief.md、characters.yaml、scenes.yaml、style.md、shots.json，不要调用生成模型，不要覆盖已有文件。

    Copilot 最适合补强：

    • scripts/validate_shots.py：检查总时长、必填字段、quality_tier、风险镜头。
    • scripts/build_ffmpeg_timeline.py：根据 edit_decision.json 生成 FFmpeg concat、字幕和混音命令。
    • 修复 provider 配置、Python/Node 工具脚本和 Remotion 组件。

    3.6 推荐协作模式¶

    助手 最适合角色 典型产物
    Codex 工程执行、批处理、合成 项目文件、脚本调用、draft.mp4、失败重试
    Claude Code 导演分析、高质量分镜 director_plan.md、shots.json、风险镜头和提示词
    OpenCode 工作流编排、团队 SOP 分阶段任务、确认门槛、生产记录

    中等质量项目可用 Codex/OpenCode 单助手直接跑完整 pipeline；高质量项目建议采用：

    Claude Code 做导演分析和高质量分镜
  -> Codex 或 OpenCode 执行 OpenMontage pipeline、provider 调用和合成
  -> Copilot 辅助写校验脚本、FFmpeg 脚本和修配置
  -> 人工审核角色、关键帧、draft、版权和最终发布版本

    落地时要坚持 5 个原则：先读指令、先做 preflight、先关键帧后视频、按镜头质量分层、保留可追溯元数据。

    五、生成分镜 shots.json¶

    5.1 分镜原则¶

    AI 短剧不适合一次生成整集，建议拆成 10-15 个镜头，每个镜头 4-8 秒。这样可以单独重做失败镜头，避免整片报废。

    90 秒短剧
  -> 拆成 10-15 个镜头
  -> 每个镜头 4-8 秒
  -> 每个镜头独立生成视频
  -> 最后统一剪辑合成

    5.2 分镜字段¶

    字段 作用
    shot_id 方便追踪、重试、返工
    duration 控制总时长和节奏
    scene_id 绑定场景卡
    characters 绑定角色参考图
    shot_type 远景、中景、近景、特写
    camera 推近、横移、固定、手持
    action 角色动作
    dialogue 对白或旁白
    emotion 指导 TTS 和表演
    visual_prompt 图像/视频生成提示词
    negative_prompt 排除畸形、错脸、文字、水印
    audio BGM、SFX、环境音

    5.3 分镜 JSON 示例¶

    {
  "project_id": "rainy_reunion_ep01",
  "title": "雨夜重逢",
  "duration_seconds": 90,
  "aspect_ratio": "9:16",
  "resolution": "1080x1920",
  "shots": [
    {
      "shot_id": "S01",
      "duration": 5,
      "scene_id": "office_entrance_rainy_night",
      "characters": ["lin_xiao"],
      "shot_type": "wide",
      "camera": "固定远景，轻微推近",
      "action": "林晓撑伞从写字楼门口走出，神情疲惫",
      "dialogue": "",
      "emotion": "疲惫、压抑",
      "visual_prompt": "vertical cinematic shot, rainy night outside modern office building, young Chinese woman with short hair wearing white shirt and light trench coat holding umbrella, wet ground reflections, cold blue-gray lighting, shallow depth of field",
      "negative_prompt": "cartoon, anime, distorted face, extra fingers, text, watermark",
      "audio": {
        "sfx": ["heavy rain", "distant traffic"],
        "bgm": "low emotional piano"
      }
    }
  ]
}

    六、选择或自定义 OpenMontage Pipeline¶

    6.1 推荐 pipeline¶

    场景 推荐 pipeline 说明
    真人感短剧 cinematic 电影感、写实画面、剧情镜头
    AI 漫剧/动态漫 character-animation 角色一致性、关键帧动画
    素材 + AI 镜头混合 hybrid stock 素材、AI 镜头、字幕混合
    数字人口播短剧 avatar-spokesperson 正脸讲话、课程、产品口播
    真实素材纪录风 documentary-montage 使用真实 footage 和旁白

    6.2 自定义短剧 pipeline 示例¶

    可创建：

    pipeline_defs/ai_micro_drama.yaml

    简化结构：

    id: ai_micro_drama
name: AI Micro Drama
aspect_ratio: "9:16"
resolution: "1080x1920"
render_runtime: ffmpeg

stages:
  - id: ingest_script
    input:
      - projects/{project_id}/script.md
      - projects/{project_id}/characters.yaml
      - projects/{project_id}/scenes.yaml
    output:
      - projects/{project_id}/shots.json
    quality_gate: human_review

  - id: scene_plan
    input:
      - projects/{project_id}/shots.json
    output:
      - projects/{project_id}/production_plan.json
    quality_gate: shot_review

  - id: keyframes
    tools:
      - image_selector
    output:
      - projects/{project_id}/assets/keyframes/
    checkpoint: true

  - id: video_generation
    tools:
      - video_selector
    output:
      - projects/{project_id}/assets/clips/
    checkpoint: true

  - id: audio
    tools:
      - tts_selector
      - music_selector
      - audio_processing
    output:
      - projects/{project_id}/assets/audio/
    checkpoint: true

  - id: subtitles
    tools:
      - transcription
      - subtitle_generator
    output:
      - projects/{project_id}/assets/subtitles/

  - id: edit
    tools:
      - video_post
      - audio_processing
    output:
      - projects/{project_id}/edit_decision.json

  - id: compose
    renderer: ffmpeg
    output:
      - projects/{project_id}/outputs/final.mp4
    validate:
      - subtitle_present
      - audio_levels
      - no_black_frames
      - duration_match

    七、中等质量制作方案¶

    中等质量适合样片、账号试水、普通短剧栏目，目标是成本可控、流程稳定、快速出片。

    7.1 模型和工具组合¶

    环节 推荐组合 说明
    剧本结构化 DeepSeek/通义千问/Kimi 中文剧本拆解、分镜 JSON 成本低
    角色图 即梦/通义万相/FLUX via fal.ai 先做角色定稿图
    关键帧 FLUX/SDXL/即梦 每个镜头先生成关键帧
    视频生成 Kling/MiniMax/WAN 2.1 1.3B 关键帧转视频，动作简单
    Stock 素材 Pexels/Pixabay/Unsplash 空镜、城市、雨夜、转场
    TTS OpenAI TTS/MiniMax/Piper 角色对白可用中价 TTS
    BGM/SFX 剪映音效库/Pixabay/Suno 免费层 避免版权风险
    字幕 Whisper/faster-whisper/剪映 先配音，再生成字幕
    合成 FFmpeg 自动拼接、压字幕、混音
    人工精修 剪映/CapCut 最后节奏微调

    7.2 中等质量配置思路¶

    quality_profile: medium

providers:
  llm:
    primary: deepseek
    fallback: qwen
  image:
    primary: flux
    fallback: local_diffusion
  video:
    primary: kling
    fallback: wan2.1-1.3b
  tts:
    primary: openai_tts
    fallback: piper
  stock:
    primary: pexels
    fallback: pixabay
  renderer:
    primary: ffmpeg

budget:
  total_cap: 20.00
  per_shot_retry_limit: 2
  confirm_threshold: 1.00

    7.3 中等质量执行步骤¶

    第 1 步：剧本清洗¶

    让 LLM 把剧本转换为生产格式：

    请把以下短剧剧本转换为 90 秒竖屏 AI 短剧生产格式：
1. 拆成 10-15 个镜头。
2. 每个镜头 4-8 秒。
3. 每个镜头包含 shot_id、duration、scene、characters、action、dialogue、emotion、visual_prompt、negative_prompt、audio。
4. 角色外观必须使用 characters.yaml 中的固定描述。
5. 输出 JSON。

    产物：shots.json。

    第 2 步：人工审查分镜¶

    重点检查：

    • 总时长是否接近目标时长。
    • 前 3 秒是否有钩子。
    • 是否每 15-20 秒有情绪转折。
    • 是否有太多双人正脸对白。
    • 是否有复杂动作、打斗、拥抱、多人混乱镜头。
    • 是否每个镜头都能独立生成。

    中等质量建议：正脸对白少一点，侧脸、背影、反应镜头多一点；复杂动作拆短，不强求口型完全同步。

    第 3 步：生成角色定稿图¶

    每个主角至少生成：

    正面半身
侧面半身
全身
常用表情 3 张

    中等质量可用工具：即梦、通义万相、FLUX、SDXL。

    角色提示词示例：

    young Chinese woman, 25 years old, short hair, white shirt, light trench coat, natural makeup, cinematic portrait, realistic drama style, soft cold lighting, neutral background, consistent facial features

    负面提示词：

    anime, cartoon, heavy makeup, different clothes, long hair, distorted face, extra fingers, text, watermark

    第 4 步：生成关键帧¶

    每个镜头生成 1-2 张候选关键帧。剧情关键镜头生成 2-3 张候选，普通对白镜头生成 1-2 张候选，空镜过渡优先 stock 素材。

    人工检查：

    • 角色脸是否稳定。
    • 服装是否一致。
    • 场景是否符合。
    • 是否有文字乱码、水印、畸形手。
    • 构图是否适合 9:16。

    第 5 步：图生视频¶

    中等质量推荐：

    Provider 用途
    Kling 人物动作、雨夜、剧情镜头
    MiniMax 低成本短镜头
    WAN 2.1 1.3B 本地低成本补充
    Pexels/Pixabay 空镜、城市、雨、街道

    镜头生成提示词：

    Use the provided keyframe as visual reference. Create a 5-second vertical cinematic video. The woman slowly stops walking and looks shocked. Subtle camera push-in, rainy night, cold blue-gray lighting, realistic drama style. Keep face, hairstyle and clothing consistent. No sudden motion.

    参数建议：

    duration: 4-6s
motion: low / medium
camera: subtle push-in / static / slow pan
retry_limit: 2
resolution: 720p or 1080p

    尽量避免大幅奔跑、复杂打斗、多人互动、大幅转身、长时间正脸说话。

    第 6 步：生成配音¶

    从 shots.json 提取对白：

    [
  {
    "shot_id": "S02",
    "speaker": "lin_xiao",
    "text": "你怎么会在这里？",
    "emotion": "震惊、克制"
  }
]

    中等质量 TTS 选择：OpenAI TTS、MiniMax、Piper。

    第 7 步：BGM 和音效¶

    建议使用低沉钢琴、轻弦乐、雨声、远处车流、脚步声和雷声。

    音量建议：

    对白：-6 dB ~ -3 dB
BGM：比对白低 12-18 dB
环境音：比对白低 15-20 dB

    第 8 步：字幕¶

    流程：

    TTS 音频
  -> Whisper/faster-whisper 转写
  -> 生成 SRT
  -> 人工修正
  -> FFmpeg 压字幕

    字幕建议：底部居中，白字黑描边，每行 14-18 个中文字符，避开人物脸和关键动作。

    第 9 步：自动合成¶

    OpenMontage 可根据 edit decision 合成：

    {
  "timeline": [
    {
      "shot_id": "S01",
      "video": "assets/clips/S01.mp4",
      "start": 0,
      "duration": 5,
      "audio": ["assets/sfx/rain.wav"]
    }
  ],
  "bgm": "assets/audio/bgm/piano_rain.wav",
  "subtitles": "assets/subtitles/final.srt",
  "output": "outputs/rainy_reunion_ep01_medium.mp4"
}

    第 10 步：质检和返工¶

    中等质量重点看总时长、字幕错字、声音清晰度、角色漂移、严重畸形镜头和前 3 秒吸引力。

    返工优先级：

    严重错脸 > 字幕错字 > 音画不同步 > 节奏拖沓 > 画面质感不足

    八、高质量制作方案¶

    高质量适合精品漫剧、品牌样片、商业投放和连载 IP，重点是角色一致性、画面质量、情绪表达、音画同步和可复用资产库。

    8.1 高质量模型和工具组合¶

    环节 推荐组合 说明
    剧本拆解 Claude/GPT/Gemini/DeepSeek 复核 复杂剧情、分镜逻辑、节奏审查
    角色设定 Midjourney/FLUX/SDXL + LoRA 角色定稿、风格板、表情库
    角色一致性 LoRA/IP-Adapter/ControlNet/平台角色档案 连载短剧必须做
    关键帧 FLUX/Imagen/Midjourney/SDXL 工作流 每镜头 2-4 张候选
    视频生成 Kling/Runway Gen-4/Veo/HeyGen/Higgsfield 关键镜头用高质量 provider
    本地兜底 WAN 2.1 14B/Hunyuan/LTX-Video 大批量、过渡镜头、成本控制
    口型同步 HeyGen/Wav2Lip/平台 lip-sync 正脸对白重点镜头
    TTS ElevenLabs/MiniMax/Google TTS/专业配音 多角色声线稳定
    BGM/SFX Suno/ElevenLabs SFX/版权音乐库 商业项目要留授权
    字幕 Whisper large/人工校对 高准确率
    合成 FFmpeg + 剪映/Premiere/DaVinci 自动初剪 + 人工精修
    质检 OpenMontage post-render review + 人工审片 商业化必须

    8.4 高质量分镜策略¶

    把镜头分成三类：

    镜头类型 示例 生成策略
    Hero Shot 情绪爆发、反转、拥抱、结尾悬念 最强图像 + 最强视频模型，多次重试
    Dialogue Shot 对白、反应、情绪铺垫 中高质量模型，注意口型和表情
    Utility Shot 空镜、转场、环境、道具 stock 或本地模型，降低成本

    shots.json 可增加质量等级：

    {
  "shot_id": "S08",
  "quality_tier": "hero",
  "duration": 7,
  "characters": ["lin_xiao", "lu_chuan"],
  "action": "陆川说出真相，林晓眼眶泛红",
  "dialogue": "当年的事，不是你想的那样。",
  "generation_strategy": {
    "image_provider": "flux",
    "video_provider": "kling_or_runway",
    "retry_limit": 5,
    "requires_human_review": true,
    "lipsync_required": true
  }
}

    8.5 高质量生成步骤¶

    第 1 步：剧本分析与导演方案¶

    让 LLM 输出故事核心冲突、角色关系、情绪曲线、90 秒节奏表、镜头分配、Hero Shot 列表、风险镜头列表和替代镜头方案。产物为 director_plan.md。

    第 2 步：分镜 JSON 生成¶

    输出 shots.json、production_plan.json、risk_shots.json。

    risk_shots.json 示例：

    [
  {
    "shot_id": "S09",
    "risk": "正脸对白较长，口型同步风险高",
    "solution": "拆成正脸开口 + 侧脸反应 + 手部特写"
  },
  {
    "shot_id": "S11",
    "risk": "两人拉扯动作复杂",
    "solution": "改为手腕特写 + 林晓回头特写"
  }
]

    第 3 步：角色一致性处理¶

    高质量优先级：

    LoRA / IP-Adapter / ControlNet
  > 平台角色档案
  > 多参考图
  > 单张参考图

    连载短剧建议先用 30-50 张角色图训练 LoRA；每个镜头关键帧都带 LoRA 或角色参考；不同场景只换光线，不轻易换服装和发型。

    第 4 步：关键帧生成¶

    生成策略：

    Hero Shot：4-8 张候选
Dialogue Shot：2-4 张候选
Utility Shot：1-2 张候选或 stock

    关键帧人工打分维度：角色一致性、构图、情绪、场景、后续视频可动性、版权风险。

    第 5 步：视频片段生成¶

    高质量模型选择：

    模型/工具 适合场景
    Kling 人物动作、剧情镜头、中文生态
    Runway Gen-4 广告感、镜头质感、电影化
    Veo 高质量物理和镜头表现
    HeyGen 数字人、正脸口播、口型同步
    Higgsfield 角色一致性和特定风格镜头
    WAN 2.1/Hunyuan 本地补充、过渡镜头

    生成策略：

    Hero Shot：优先 Kling / Runway / Veo，重试 3-5 次，必要时首尾帧控制
Dialogue Shot：使用 Kling / HeyGen / lip-sync 工具，避免长正脸说话
Utility Shot：使用 stock footage / WAN / LTX，成本优先

    第 6 步：对白与口型¶

    高质量短剧最好采用：

    先生成 TTS
  -> 根据音频长度调整镜头
  -> 需要正脸对白的镜头做 lip-sync
  -> 不需要口型的镜头用侧脸、背影、反应镜头

    正脸对白处理：

    ElevenLabs / MiniMax 生成对白
  -> HeyGen / Wav2Lip / 平台 lip-sync
  -> 回填到对应 shot

    如果口型不稳，将正脸对白镜头改为角色反应特写，台词改成画外音。

    第 7 步：音乐和音效设计¶

    高质量不建议只铺一条 BGM，而应分层：

    主 BGM：情绪底色
环境音：雨声、车流、风声
动作音效：脚步、衣服摩擦、拉手、开门
情绪音效：低频冲击、悬念上升、结尾 stinger

    音频目录：

    assets/audio/
  dialogue/
  bgm/
  sfx/
  ambience/
  mix/

    第 8 步：字幕和包装¶

    高质量字幕需要人工校对、固定字体、固定描边、固定安全边距，关键台词可加轻微强调。可增加片头、剧集标题、结尾悬念字幕、关注或下一集 CTA。

    第 9 步：自动初剪¶

    video clips
  + dialogue
  + sfx
  + bgm
  + subtitles
  + intro/outro
  -> draft.mp4

    建议先输出：

    outputs/draft_v1.mp4
outputs/qc_report_v1.md

    第 10 步：人工精修¶

    高质量必须人工过一遍，可使用剪映、Premiere、DaVinci Resolve 或 CapCut。精修内容包括节奏、停顿、字幕断句、音量、调色、不稳定镜头替换、片头片尾和平台适配版本。

    十一、推荐实际生产顺序¶

    1. 先做 30-45 秒样片：不要一开始就做完整 3 分钟。
    2. 只选 2 个主角 + 1 个主场景：降低一致性难度。
    3. 把剧本拆成 6-8 个镜头：每个镜头 4-6 秒。
    4. 先生成角色图和场景图：不要直接生成视频。
    5. 每个镜头先出关键帧：人工选图后再转视频。
    6. 先配音再剪辑：用音频决定镜头节奏。
    7. 正脸对白少用：口型不稳就改成旁白、侧脸、背影、反应镜头。
    8. OpenMontage 自动合成初版：用 FFmpeg 输出 draft。
    9. 人工只修最影响观感的 20% 问题：错脸、错字、音量、节奏。
    10. 数据验证后再升级高质量 pipeline：不要在第一条就过度投入。

    十二、结论¶

    用 OpenMontage 做 AI 短剧，最稳的路线是：

    剧本
  -> 角色卡/场景卡/风格板
  -> shots.json 分镜
  -> 关键帧
  -> 图生视频
  -> TTS/BGM/字幕
  -> FFmpeg/Remotion/HyperFrames 合成
  -> 分阶段质检和返工
  -> 最终成片

    中等质量重在 快、稳、省钱；高质量重在 角色资产、关键帧、口型、声音、质检和人工精修。OpenMontage 的价值不是替代所有创作判断，而是把这套流程标准化、可恢复、可复用、可批量生产。
