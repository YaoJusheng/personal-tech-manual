    一、为什么需要分布式训练¶

    1.1 模型规模爆炸¶

    近年来，深度学习模型的参数量呈指数级增长。从 BERT 的 3.4 亿到 GPT-3 的 1750 亿，再到 Llama 3 的 4050 亿参数，单个 GPU 的显存（即使是最新的 H100 80GB）远无法容纳完整模型。

    时期 代表模型 参数量 GPU 卡数 训练时长 训练数据量
    2018 BERT-Large 340M 64 TPU v2 ~4 天 3.3B tokens
    2020 GPT-3 175B ~10000 GPU (V100) ~数月 300B tokens
    2022 PaLM 540B 6144 TPU v4 ~50 天 780B tokens
    2023 Llama 2 70B 70B 2000 GPU (A100) ~21 天 2T tokens
    2024 Llama 3 405B 405B 30720 GPU (H100) ~54 天 15T tokens

    关键趋势：

    • 每 2-3 年模型参数量增长约 10 倍
    • 单 GPU 显存增长约 2 倍/代（V100 32GB → A100 80GB → H100 80GB）→ 远落后于模型增长
    • 训练数据量从 GB 级别跃升至 TB 级别
    • 单卡训练已完全不可行，分布式训练成为必修课

    1.2 单 GPU 的局限¶

    瓶颈 说明 具体数值示例
    显存墙（Memory Wall） 模型参数、优化器状态、中间激活的总和远超单卡显存 Llama 2 70B 在 BF16 下：参数 140GB + 优化器状态 280GB + 激活约 100GB = 520GB > H100 的 80GB
    计算墙（Compute Wall） 单卡算力有限，训练时间不可接受 单卡 A100 训练 Llama 2 70B 约需 172 年
    数据墙（Data Wall） 数据加载速度跟不上 GPU 计算速度 GPU 处理一个 batch 仅需 0.1s，但磁盘读取可能耗时 0.5s → GPU 空闲等待

    1.3 Scaling Laws（缩放定律）¶

    OpenAI 2020 年提出的 Scaling Laws 揭示了模型性能与计算量之间的幂律关系：

    \[L(N, D) \propto N^{-\alpha} + D^{-\beta}\]

    其中 \(N\) 为参数量，\(D\) 为数据量，\(\alpha\) 和 \(\beta\) 为经验常数。这意味着：

    • 更大的模型 + 更多的数据 → 可预测的性能提升
    • 但需要相应的计算资源支撑
    • 分布式训练是打破单卡瓶颈、遵循 Scaling Laws 的唯一途径

    二、分布式训练基础概念¶

    2.1 并行策略总览¶

    分布式训练的并行策略从多个维度切分计算和显存，以下是完整的策略层次结构：

                                      ┌──────────────────────────────────────────────────────────┐
                                  │                   并行策略层次结构                          │
                                  ├──────────────────────────────────────────────────────────┤
                                  │                                                          │
                                  │    ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐│
                                  │    │ 数据并行 │  │ 张量并行 │  │ 流水线并行│  │ 序列并行 ││
                                  │    │  Data    │  │  Tensor  │  │ Pipeline │  │ Sequence ││
                                  │    │ Parallel │  │ Parallel │  │ Parallel │  │ Parallel ││
                                  │    └─────┬────┘  └─────┬────┘  └─────┬────┘  └─────┬────┘│
                                  │          │              │              │              │     │
                                  │          └──────────────┴──────────────┴──────────────┘     │
                                  │                          ↓                                  │
                                  │              ┌───────────────────────┐                      │
                                  │              │   3D / 4D 混合并行    │                      │
                                  │              │ (TP + PP + DP + SP)  │                      │
                                  │              └───────────────────────┘                      │
                                  │                                                          │
                                  └──────────────────────────────────────────────────────────┘

    各并行策略的直观类比：

    策略 类比 切分维度
    数据并行（DP） 多个学生各自做一套完整试卷，做完后对答案 数据批次
    张量并行（TP） 一道数学题的不同计算步骤分给不同人同时算 层内计算
    流水线并行（PP） 工厂流水线，每个工位完成一道工序 层间切分
    序列并行（SP） 一篇长文章各人读一段，通过讨论理解全文 序列长度
    专家并行（EP） 各科专家各司其职，问题分派给对应专家 模型宽度

    2.2 数据并行（Data Parallelism, DP & DDP）¶

    原理：每个 GPU 持有完整的模型副本，将全局 batch 切分为微批次（micro-batch）分发给各 GPU，各自独立前向/反向传播，然后通过 All-Reduce 通信同步梯度。

                     ┌─────────────────────────────────────────┐
                 │              训练数据 (Global Batch)       │
                 └──────┬──────────────┬──────────────┬──────┘
                        │              │              │
                   Micro-batch     Micro-batch    Micro-batch
                        ↓              ↓              ↓
              ┌─────────────────────────────────────────────┐
              │    GPU 0          GPU 1          GPU 2      │
              │  ┌─────────┐   ┌─────────┐   ┌─────────┐   │
              │  │ 模型副本 │   │ 模型副本 │   │ 模型副本 │   │
              │  ├─────────┤   ├─────────┤   ├─────────┤   │
              │  │ 前向→损失│   │ 前向→损失│   │ 前向→损失│   │
              │  │ 反向→梯度│   │ 反向→梯度│   │ 反向→梯度│   │
              │  └────┬────┘   └────┬────┘   └────┬────┘   │
              └───────┼─────────────┼──────────────┼────────┘
                      │             │              │
                      └─────────────┼──────────────┘
                                   ↓
                         All-Reduce（梯度同步）
                                   ↓
                          各卡获得平均梯度
                                   ↓
                          各卡独立更新参数
                                   ↓
                        进入下一个训练步（所有卡参数一致）

    Naive DataParallel（不推荐）：

    # torch.nn.DataParallel —— 遗留方案，不推荐使用
model = nn.DataParallel(model)   # 主卡收集梯度，负载不均

    缺点：单进程多线程模型，GIL 限制，主卡（rank 0）负载远超其他卡，仅支持单机。

    DistributedDataParallel（推荐）：

    # torch.nn.parallel.DistributedDataParallel — 标准方案
model = DDP(model, device_ids=[local_rank])

    DDP vs DP 对比：

    维度 DataParallel (DP) DistributedDataParallel (DDP)
    进程模型 单进程多线程 多进程（每卡一个进程）
    通信方式 主卡收集→广播 All-Reduce（Ring 算法）
    负载均衡 主卡负载高（收集+分发） 各卡均衡
    多节点支持 不支持 支持
    性能 慢（受 GIL 影响） 快（接近线性加速）
    推荐度 已废弃 标准选择

    2.3 张量并行（Tensor Parallelism, TP）¶

    原理：将单层内的矩阵运算切分到多个 GPU 上并行执行。以 Megatron-LM 风格为例，对 Transformer 的 FFN 和 Attention 层做列切分（column-wise）和行切分（row-wise）。

    FFN 层张量并行示意图：

    标准 FFN（单卡）：
  输入 x (hidden)
    │
    ↓
  Linear(hidden → 4×hidden)  →  激活  →  Linear(4×hidden → hidden)
    ↑                                  ↑
  单卡计算整个矩阵乘                  单卡计算整个矩阵乘

张量并行 FFN（2-way TP，两台 GPU）：
                 输入 x (hidden)
                  │        │
          ┌───────┘        └───────┐
          ↓                        ↓
     GPU 0: Linear 列切分      GPU 1: Linear 列切分
     W₁ 前一半列 (h→2h)        W₁ 后一半列 (h→2h)
          ↓                        ↓
     ReLU                      ReLU
          ↓                        ↓
     GPU 0: Linear 行切分      GPU 1: Linear 行切分
     W₂ 前一半行 (2h→h)        W₂ 后一半行 (2h→h)
          ↓                        ↓
          └────────┬───────────────┘
                   ↓
             All-Reduce 求和
                   ↓
               输出 y (hidden)

    通信量分析：每个 Transformer 层需要 2 次 All-Reduce（Attention 输出一次 + FFN 输出一次），通信量与 hidden_size 成正比。

    代码示例（概念性）：

    # 2-way 张量并行的 Linear 层（概念代码）
class MegatronColumnParallelLinear(nn.Module):
    """列切分 Linear：将输出维度切分到多卡"""

    def __init__(self, input_size, output_size, parallel_size=2):
        super().__init__()
        self.parallel_size = parallel_size
        # 每卡只保存 output_size / parallel_size 的列
        self.weight = nn.Parameter(
            torch.randn(output_size // parallel_size, input_size)
        )

    def forward(self, x):
        # 每卡独立计算自己的部分
        output_part = F.linear(x, self.weight)
        # 注意：这里需要 All-Gather 或 All-Reduce 来合并结果
        return output_part


class MegatronRowParallelLinear(nn.Module):
    """行切分 Linear：将输入维度切分到多卡"""

    def __init__(self, input_size, output_size, parallel_size=2):
        super().__init__()
        self.parallel_size = parallel_size
        # 每卡只保存 input_size / parallel_size 的行
        self.weight = nn.Parameter(
            torch.randn(output_size, input_size // parallel_size)
        )

    def forward(self, x):
        # 这里输入的 parallel 部分已经就绪
        output = F.linear(x, self.weight)
        # 需要 All-Reduce 汇总各卡结果
        return output

    2.4 流水线并行（Pipeline Parallelism, PP）¶

    原理：将模型的层切分到多个 stage（阶段），每个 GPU 负责一个连续层段。数据以 micro-batch 形式在各 stage 间流转。

    朴素流水线（低效）：

    时间 ──────────────────────────────────────────────→
                    │ GPU 0 (Layers 1-4) │ GPU 1 (Layers 5-8) │ GPU 2 (Layers 9-12)
                    │                    │                     │
微批次 1 (mb1):     │ F1                 │ 闲置                │ 闲置
微批次 2 (mb2):     │ F2                 │ F1                  │ 闲置
微批次 3 (mb3):     │ F3                 │ F2                  │ F1
                    │        大量 GPU 空闲 Bubble               │

    GPipe 方案：将 batch 拆分为多个 micro-batch，填满流水线后进入 steady state。

    1F1B（One-Forward-One-Backward）调度：这是当前最主流的流水线调度策略。前向和反向交叠执行，减少显存占用和 idle time：

    时间 ────────────────────────────────────────────────────────────────────→
Stage │  Step 1  │  Step 2  │  Step 3  │  Step 4  │  Step 5  │  Step 6  │
──────┼──────────┼──────────┼──────────┼──────────┼──────────┼──────────│
GPU 0 │ F(mb1)   │ F(mb2)   │ F(mb3)   │ B(mb3)   │ B(mb2)   │ B(mb1)   │
GPU 1 │ 闲置     │ F(mb1)   │ F(mb2)   │ F(mb2)←B │ F(mb1)←B │ B(mb1)   │
GPU 2 │ 闲置     │ 闲置     │ F(mb1)   │ F(mb1)   │ B(mb1)   │ B(mb1)←F │
       │                   ↑ 流水线填充期 ↑    │    ↑ 稳态 + 排空期 ↑    │

其中：F = Forward（前向）, B = Backward（反向）
注：GPU 1 和 GPU 2 的 B(mb)←F 表示先完成当前 micro-batch 的 backward，
    紧接开始下一个 micro-batch 的 forward（交叠执行）

    流水线 Bubble 占比估算：

    \[Bubble\ Ratio = \frac{P-1}{M} \approx \frac{P-1}{4 \times \text{micro-batches}}\]

    其中 \(P\) 为流水线段数，\(M\) 为 micro-batch 总数。\(P=8, M=32\) 时，bubble 占比约 22%。

    代码示例：

    # PyTorch 流水线 Pipe 封装（简化示例）
from torch.distributed.pipeline.sync import Pipe

# 将模型切分为 4 个 stage，部署在 4 张 GPU 上
model = nn.Sequential(
    nn.Linear(4096, 4096),  # Stage 0: GPU 0
    nn.Linear(4096, 4096),  # Stage 1: GPU 1
    nn.Linear(4096, 4096),  # Stage 2: GPU 2
    nn.Linear(4096, 4096),  # Stage 3: GPU 3
)
model = Pipe(model, chunks=8)  # 8 个 micro-batch 填充分段

# 前向传播自动拆分 micro-batch 并流水线执行
output = model(torch.randn(64, 4096))

    说明：torch.distributed.pipeline.sync.Pipe 基于 GPipe 论文实现，1F1B 调度需借助 DeepSpeed 的 Pipeline Engine 或 Megatron-LM。

    2.5 序列并行（Sequence Parallelism, SP）¶

    原理：将序列长度维度切分到多个 GPU，每个 GPU 只计算部分 token 的注意力。解决长序列场景下注意力计算的显存爆炸问题。

    三种主流实现：

    方法 原理 通信模式 适用场景
    Megatron-LM SP 在 LayerNorm + Dropout 上沿序列维度切分，配合 TP 使用 All-Gather / Reduce-Scatter 与 TP 结合，降低激活显存
    Ring Attention 将序列分块到多卡，通过环形传递计算完整注意力 点对点环形通信 超长序列（128K+ tokens）
    DeepSpeed Ulysses 将 Q/K/V 切分，通过 All-to-All 通信重组 All-to-All 长序列 + 大规模并行

    使用场景：上下文长度超过 32K tokens 时，标准注意力计算的 O(n²) 显存开销急剧增大。序列并行可以将每卡的序列长度减半/减四分之一，使长上下文训练成为可能。

    2.6 混合专家并行（MoE + Expert Parallelism, EP）¶

    原理：MoE（Mixture of Experts）模型包含多个"专家"子网络，每个 token 经路由（Router）选择激活少数专家。专家并行将不同专家部署在不同设备上。

                       输入 Tokens [A, B, C, D, E, F]
                             │
                             ↓
                      ┌──────────────┐
                      │   Router     │  ← 轻量门控网络
                      │  (Gate)      │
                      └──────┬───────┘
                             │ 每个 token 被路由到 Top-2 专家
              ┌──────────────┼──────────────────┐
              │              │                   │
              ↓              ↓                   ↓
         ┌─────────┐   ┌─────────┐         ┌─────────┐
         │ Expert 0│   │ Expert 1│   ...    │ Expert 7│   ← 每个专家部署在不同的 GPU 上
         │ (GPU 0) │   │ (GPU 1) │         │ (GPU 7) │
         └────┬────┘   └────┬────┘         └────┬────┘
              │             │                    │
              └─────────────┼────────────────────┘
                            ↓
                   输出 Tokens (合并)

    关键组件：

    • Router（门控网络）：通常是一个轻量线性层 + Softmax，计算每个 token 分配到各专家的概率
    • Top-k 路由：每个 token 只激活 k 个专家（通常 k=1 或 k=2），其余专家不参与计算
    • 负载均衡损失（Auxiliary Loss）：额外损失项，鼓励 tokens 均匀分配到各专家，防止路由崩溃

    MoE 参数量推算：

    MoE 参数总量 = Dense 参数 + Expert 参数

以 Mixtral 8×7B 为例：
  - 每个专家是 7B 参数
  - 共 8 个专家，但共享一些层（如注意力层不 MoE 化）
  - 实际总参数量约 47B
  - 但推理时每个 token 只激活 2 个专家 → 计算量约 12.9B（接近 13B 的密集模型）

    三、核心分布式训练工具详解¶

    3.1 PyTorch DDP（DistributedDataParallel）¶

    PyTorch DDP 是最基础、最广泛使用的分布式训练方案。它通过多进程 + All-Reduce 实现高效数据并行。

    3.1.1 启动方式¶

    torchrun（推荐）：

torchrun --nproc_per_node=8 --nnodes=2 --node_rank=0 \

    3.1.2 通信后端对比¶

    后端 GPU 支持 CPU 支持 适用场景 特点
    NCCL GPU 分布式训练（首选） NVIDIA 官方，GPU 通信最优，支持 NVLink/InfiniBand
    GLOO CPU 训练 / GPU 调试 CPU 上表现好，GPU 上不如 NCCL 高效
    MPI HPC 环境 需要 MPI 库（OpenMPI, MPICH），灵活但配置复杂

    3.1.3 完整 DDP 训练脚本¶

    # train_ddp.py — 完整的 DDP 训练脚本
import os
import torch
import torch.nn as nn
import torch.distributed as dist
import torch.nn.functional as F
from torch.nn.parallel import DistributedDataParallel as DDP
from torch.utils.data import Dataset, DataLoader
from torch.utils.data.distributed import DistributedSampler


def setup(rank, world_size):
    """初始化分布式进程组"""
    # 环境变量方式（由 torchrun 自动设置）
    dist.init_process_group(
        backend="nccl",           # GPU 训练用 NCCL
        init_method="env://",     # 从环境变量读取 MASTER_ADDR / MASTER_PORT
        world_size=world_size,
        rank=rank,
    )
    torch.cuda.set_device(rank)


def cleanup():
    """销毁进程组"""
    dist.destroy_process_group()


class SimpleTransformerBlock(nn.Module):
    """简化的 Transformer 层用于演示"""

    def __init__(self, hidden=4096, ffn_hidden=11008):
        super().__init__()
        self.attention = nn.Linear(hidden, hidden)
        self.ffn = nn.Sequential(
            nn.Linear(hidden, ffn_hidden),
            nn.GELU(),
            nn.Linear(ffn_hidden, hidden),
        )
        self.norm1 = nn.LayerNorm(hidden)
        self.norm2 = nn.LayerNorm(hidden)

    def forward(self, x):
        # 自注意力 + 残差
        x = x + self.attention(self.norm1(x))
        # FFN + 残差
        x = x + self.ffn(self.norm2(x))
        return x


class ToyModel(nn.Module):
    """演示用模型，模拟 1.3B 参数规模"""

    def __init__(self, hidden=2048, num_layers=12, vocab=32000):
        super().__init__()
        self.embed = nn.Embedding(vocab, hidden)
        self.layers = nn.ModuleList([
            SimpleTransformerBlock(hidden) for _ in range(num_layers)
        ])
        self.norm = nn.LayerNorm(hidden)
        self.lm_head = nn.Linear(hidden, vocab)

    def forward(self, input_ids):
        x = self.embed(input_ids)
        for layer in self.layers:
            x = layer(x)
        x = self.norm(x)
        logits = self.lm_head(x)
        return logits


def train_ddp(rank, world_size):
    """DDP 训练主函数（由 torchrun 启动）"""
    print(f"启动进程 rank={rank}, world_size={world_size}")
    setup(rank, world_size)

    # ===== 1. 创建模型并包装 DDP =====
    model = ToyModel().to(rank)
    model = DDP(model, device_ids=[rank], output_device=rank)

    # ===== 2. 创建分布式数据加载器 =====
    # 使用 DistributedSampler 自动为每个进程分配数据子集
    dataset = torch.randn(1000, 128).to(rank)  # 模拟数据集
    labels = torch.randint(0, 32000, (1000, 128)).to(rank)
    sampler = DistributedSampler(
        dataset,
        num_replicas=world_size,   # 总进程数
        rank=rank,                  # 当前进程 rank
        shuffle=True,               # 每个 epoch 打乱
    )
    loader = DataLoader(
        list(zip(dataset, labels)),
        batch_size=4,
        sampler=sampler,            # 使用 sampler 替代 shuffle
    )

    # ===== 3. 配置优化器 =====
    optimizer = torch.optim.AdamW(model.parameters(), lr=1e-4)

    # ===== 4. 训练循环 =====
    model.train()
    for epoch in range(3):
        # 重要：每个 epoch 设置 sampler 的 epoch，确保不同 epoch 不同打乱顺序
        sampler.set_epoch(epoch)

        for batch_idx, (data, target) in enumerate(loader):
            data, target = data.to(rank), target.to(rank)

            optimizer.zero_grad()
            output = model(data)
            loss = F.cross_entropy(
                output.view(-1, 32000),
                target.view(-1)
            )
            loss.backward()

            # 梯度裁剪（在 DDP 中只需在 rank 0 上调用，但所有 rank 都做也可以）
            torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)

            optimizer.step()

            if rank == 0 and batch_idx % 10 == 0:
                print(f"Epoch {epoch}, Batch {batch_idx}, Loss {loss.item():.4f}")

    # ===== 5. 保存模型（仅在 rank 0 上保存） =====
    if rank == 0:
        # DDP 模型通过 .module 访问原始模型
        torch.save(model.module.state_dict(), "model_ddp.pth")
        print("模型已保存")

    cleanup()


if __name__ == "__main__":
    # 由 torchrun 设置环境变量
    local_rank = int(os.environ["LOCAL_RANK"])
    world_size = int(os.environ["WORLD_SIZE"])
    train_ddp(local_rank, world_size)

    3.1.4 DDP 关键注意事项¶

    注意点 说明 代码
    DistributedSampler 必须使用，确保各进程看到不同数据 sampler.set_epoch(epoch) 每个 epoch 调用
    sync_batchnorm 分布式场景需同步 BatchNorm 统计量 model = nn.SyncBatchNorm.convert_sync_batchnorm(model)
    梯度裁剪 各进程独立裁剪，DDP 会自动同步梯度后再裁剪 clip_grad_norm_(model.parameters(), 1.0)
    模型保存 只在 rank 0 保存，访问原始模型用 .module torch.save(model.module.state_dict(), ...)
    未使用参数 find_unused_parameters=True 当模型有参数不参与梯度计算 DDP(model, find_unused_parameters=True)

    3.2 PyTorch FSDP（Fully Sharded Data Parallel）¶

    FSDP 是 PyTorch 官方实现的全分片数据并行，灵感来源于 DeepSpeed ZeRO。它将模型参数、梯度和优化器状态分片到各 GPU，需要时再按需收集（All-Gather）。

    3.2.1 FSDP vs DDP 对比¶

    显存占用对比（以 7B 模型，BF16，8×A100 80GB 为例）：

                 DDP                    FSDP (FULL_SHARD)
        ┌──────────────────┐     ┌──────────────────┐
        │   参数: 14GB      │     │   参数: 14/8=1.75GB│
        │   梯度: 14GB      │     │   梯度: 14/8=1.75GB│
        │  优化器: 28GB     │     │  优化器: 28/8=3.5GB │
        │ ────────────────  │     │ ────────────────  │
        │   激活:  可变      │     │   激活:  可变      │
        │   总计: ~56GB     │     │   总计: ~7GB+激活  │
        └──────────────────┘     └──────────────────┘
        ↑ 7B 模型勉强可装     ↑ 显存充裕，可放更大模型

    3.2.2 分片策略详解¶

    策略 对应 ZeRO Shard 内容 通信量 显存节省 适用规模
    FULL_SHARD ZeRO-3 参数 + 梯度 + 优化器状态 最高（每层前向/反向各一次 All-Gather） 最大 30B+
    SHARD_GRAD_OP ZeRO-2 梯度 + 优化器状态（参数不 shard） 中等 中等 7B-30B
    NO_SHARD DDP 无分片 最低（仅梯度 All-Reduce） 无 ≤7B
    HYBRID_SHARD ZeRO-3 + 节点内 DDP 节点内 FSDP，节点间 DDP 中高 大 多节点场景

    通信 vs 显存权衡：

    FULL_SHARD: 显存↓ 通信↑ (每层需 All-Gather 参数 → 计算 → 丢弃)
NO_SHARD:   显存↑ 通信↓ (仅梯度同步)

以 8 卡为例，FULL_SHARD 的额外通信量：
  前向: 每层一次 All-Gather（收集完整参数）
  反向: 每层一次 All-Gather（收集完整参数用于梯度计算）
       每层一次 Reduce-Scatter（分片梯度）
  总计: 每层 3 次集体通信 ≈ DDP 的 1.5 倍

    3.2.3 自动包装策略（auto_wrap_policy）¶

    FSDP 需要决定哪些子模块独立分片。auto_wrap_policy 控制包装粒度：

    from torch.distributed.fsdp import FullyShardedDataParallel as FSDP
from torch.distributed.fsdp.wrap import (
    transformer_auto_wrap_policy,
    size_based_auto_wrap_policy,
    lambda_auto_wrap_policy,
)

# ===== 策略 1：基于 Transformer 层的包装（推荐） =====
# 每个 TransformerBlock 独立分片，是 Llama/GPT 的最佳选择
from transformers.models.llama.modeling_llama import LlamaDecoderLayer

auto_wrap_policy = partial(
    transformer_auto_wrap_policy,
    transformer_layer_cls={LlamaDecoderLayer},
)

# ===== 策略 2：基于参数数量的包装 =====
# 当参数数量超过阈值时自动包装
auto_wrap_policy = partial(
    size_based_auto_wrap_policy,
    min_num_params=1e6,   # 100 万参数以上的模块才包装
)

# ===== 策略 3：自定义 Lambda =====
# 完全自定义包装规则
auto_wrap_policy = lambda module, recurse, nonwrapped_numel: (
    not recurse and nonwrapped_numel > 1e7
)

# 使用策略
model = FSDP(
    model,
    auto_wrap_policy=auto_wrap_policy,
    sharding_strategy=ShardingStrategy.FULL_SHARD,
    device_id=torch.cuda.current_device(),
)

    3.2.4 FSDP 完整训练示例¶

    # train_fsdp.py — FSDP 训练 Llama 风格模型
import torch
import torch.nn as nn
import torch.distributed as dist
from torch.distributed.fsdp import (
    FullyShardedDataParallel as FSDP,
    ShardingStrategy,
    MixedPrecision,
    CPUOffload,
    BackwardPrefetch,
)
from torch.distributed.fsdp.wrap import transformer_auto_wrap_policy
from functools import partial


class TransformerBlock(nn.Module):
    """模拟 Transformer 层"""
    def __init__(self, dim=4096):
        super().__init__()
        self.attn = nn.Linear(dim, dim)
        self.ffn = nn.Sequential(
            nn.Linear(dim, dim * 4),
            nn.ReLU(),
            nn.Linear(dim * 4, dim),
        )
        self.norm1 = nn.LayerNorm(dim)
        self.norm2 = nn.LayerNorm(dim)

    def forward(self, x):
        x = x + self.attn(self.norm1(x))
        x = x + self.ffn(self.norm2(x))
        return x


class LlamaLikeModel(nn.Module):
    """类 Llama 模型，TransformerBlock 作为 FSDP 包装粒度"""

    def __init__(self, dim=4096, n_layers=32, vocab=32000):
        super().__init__()
        self.embed = nn.Embedding(vocab, dim)
        self.layers = nn.ModuleList([
            TransformerBlock(dim) for _ in range(n_layers)
        ])
        self.norm = nn.LayerNorm(dim)
        self.lm_head = nn.Linear(dim, vocab)

    def forward(self, x):
        x = self.embed(x)
        for layer in self.layers:
            x = layer(x)
        x = self.norm(x)
        return self.lm_head(x)


def train_fsdp():
    """FSDP 训练主函数"""
    dist.init_process_group("nccl")
    rank = dist.get_rank()
    torch.cuda.set_device(rank)

    # ===== 1. 在 CPU 上创建模型，FSDP 自动移至 GPU =====
    model = LlamaLikeModel(dim=4096, n_layers=32, vocab=32000)

    # ===== 2. 配置混合精度 =====
    # FSDP 内置混合精度支持，不需要额外的 autocast
    mp_policy = MixedPrecision(
        param_dtype=torch.bfloat16,       # BF16 参数
        reduce_dtype=torch.bfloat16,      # BF16 通信（梯度）
        buffer_dtype=torch.bfloat16,      # BF16 Buffer
    )

    # ===== 3. 配置 CPU Offload（可选） =====
    # 将不参与计算的参数 offload 到 CPU，进一步节省显存
    cpu_offload = CPUOffload(offload_params=False)  # 通常只 offload 优化器状态

    # ===== 4. 包装 FSDP =====
    model = FSDP(
        model,
        sharding_strategy=ShardingStrategy.FULL_SHARD,  # ZeRO-3
        auto_wrap_policy=partial(
            transformer_auto_wrap_policy,
            transformer_layer_cls={TransformerBlock},
        ),
        mixed_precision=mp_policy,
        cpu_offload=cpu_offload,
        backward_prefetch=BackwardPrefetch.BACKWARD_PRE,  # 预取下一层参数
        device_id=torch.cuda.current_device(),
    )

    # ===== 5. 优化器 =====
    optimizer = torch.optim.AdamW(model.parameters(), lr=1e-4, weight_decay=0.01)

    # ===== 6. 训练循环 =====
    for step in range(100):
        optimizer.zero_grad()

        # 模拟输入
        input_ids = torch.randint(0, 32000, (4, 512)).cuda(rank)
        labels = input_ids.clone()

        # 前向 + 反向
        logits = model(input_ids)
        loss = nn.functional.cross_entropy(
            logits.view(-1, 32000), labels.view(-1)
        )
        loss.backward()
        optimizer.step()

        if rank == 0 and step % 10 == 0:
            print(f"Step {step}, Loss {loss.item():.4f}")

    # ===== 7. 保存（仅 rank 0） =====
    if rank == 0:
        # FSDP 需要先 gather 完整状态再保存
        state_dict = model.state_dict()
        torch.save(state_dict, "model_fsdp.pth")

    dist.destroy_process_group()


if __name__ == "__main__":
    train_fsdp()

    3.3 DeepSpeed¶

    DeepSpeed 是 Microsoft 开源的深度学习优化库，提供了 ZeRO（Zero Redundancy Optimizer）系列显存优化方案，是目前最成熟、应用最广泛的大规模训练工具之一。

    3.3.1 ZeRO 三阶段对比¶

    ZeRO Stage Optimizer States Gradients Parameters 通信量（vs DDP） 显存节省（7B, 8卡, BF16）
    ZeRO-1 Sharded Replicated Replicated ~1× 优化器 28GB → 3.5GB
    ZeRO-2 Sharded Sharded Replicated ~1× 优化器 + 梯度 42GB → 3.5GB
    ZeRO-3 Sharded Sharded Sharded ~1.5× - 3× 全部 56GB → 7GB

    显存节省详细计算（7B 模型，BF16，8 卡）：

    参数总量（BF16）： 7B × 2 bytes = 14 GB
梯度总量（BF16）： 7B × 2 bytes = 14 GB（与参数等量，反向传播存储）
优化器状态（Adam）： 7B × 2 × 4 bytes = 56 GB
  - 动量（FP32）： 7B × 4 bytes = 28 GB
  - 方差（FP32）： 7B × 4 bytes = 28 GB

DDP 每卡显存： 14 + 14 + 56 = 84 GB（7B 都无法放入 80GB 卡！）
ZeRO-3 每卡： (14 + 14 + 56) / 8 = 10.5 GB + 少量冗余

    3.4 Megatron-LM（NVIDIA）¶

    Megatron-LM 是 NVIDIA 的大规模训练框架，核心贡献是张量并行（TP）和流水线并行（PP）的高效实现。它是 GPT-3、Llama 等超大规模模型训练的基础设施。

    3.4.1 核心并行策略组合¶

    Megatron-LM 的 3D 并行：

                              Data Parallel
                         ┌───────────────────┐
                         │   DP=2            │
                         │ ┌─────┐ ┌─────┐   │
                         │ │TP=4 │ │TP=4 │   │
                         │ │PP=2 │ │PP=2 │   │
                         │ └─────┘ └─────┘   │
                         └───────────────────┘

总 GPU = DP × TP × PP = 2 × 4 × 2 = 16

    每个并行维度的角色：

    维度 切分方式 通信模式 通信量 通信频率 延迟敏感度
    TP（张量并行） 层内切分 All-Reduce 高（每层一次） 每层计算 极高（需 NVLink）
    PP（流水线并行） 层间切分 P2P 低（激活传递） 每 micro-batch 低
    DP（数据并行） 数据切分 All-Reduce 中（梯度同步） 每步一次 中

    3.4.3 关键组件¶

    1. 并行 Linear 层（ParallelMLP / ParallelAttention）：

    Megatron-LM 对 Transformer 的 FFN 和 Attention 做了 f 和 g 两个切分点：

    Attention 层：
  输入 x → Q/K/V 列切分（各卡算一部分头）→ 并行注意力 → All-Reduce → 输出

FFN 层：
  输入 x → 第一个 Linear 列切分 → 激活 → 第二个 Linear 行切分 → All-Reduce → 输出

    2. Sequence Parallelism：在 LayerNorm 和 Dropout 上沿序列维度切分，配合 TP 减少激活显存。

    3. Virtual Pipeline：将流水线进一步细分为虚拟流水线段，减少 bubble 比率。

    3.5 Horovod¶

    Horovod 是 Uber 开源的分布式训练框架，以其高效的 Ring-AllReduce 算法著称，支持多框架（TensorFlow, PyTorch, MXNet）。

    3.5.1 Ring-AllReduce 原理¶

    传统 All-Reduce（参数服务器）：
  所有 GPU 发送梯度到参数服务器 → 服务器求和后广播回去
  瓶颈：服务器带宽成为瓶颈

Ring-AllReduce（Horovod）：
  将 GPU 组织成环，梯度分片后在环上依次传递求和
  每个 GPU 只和相邻 GPU 通信
  带宽利用率最大化，延迟不随 GPU 数增长

  以 4 GPU 为例：
  Step 1: GPU0→GPU1, GPU1→GPU2, GPU2→GPU3, GPU3→GPU0（传递分片）
  Step 2: 继续传递部分和
  ... 经过 2×(N-1) 步完成

    3.5.2 Horovod + PyTorch 示例¶

    # train_horovod.py — Horovod + PyTorch
import horovod.torch as hvd
import torch
import torch.nn as nn

def train_horovod():
    # ===== 1. 初始化 Horovod =====
    hvd.init()
    torch.cuda.set_device(hvd.local_rank())

    # ===== 2. 创建模型 =====
    model = nn.Linear(4096, 4096).cuda()
    # 关键：广播初始参数，确保所有进程从同一初始状态开始
    hvd.broadcast_parameters(model.state_dict(), root_rank=0)

    # ===== 3. 包装优化器 =====
    optimizer = torch.optim.AdamW(model.parameters(), lr=1e-4)
    # Horovod 分布式优化器自动包装梯度 All-Reduce
    optimizer = hvd.DistributedOptimizer(
        optimizer,
        named_parameters=model.named_parameters(),
        compression=hvd.Compression.fp16,  # FP16 梯度压缩
    )

    # ===== 4. 数据加载（每个进程不同子集） =====
    dataset = torch.randn(1000, 4096)
    sampler = torch.utils.data.distributed.DistributedSampler(
        dataset,
        num_replicas=hvd.size(),
        rank=hvd.rank(),
    )
    loader = torch.utils.data.DataLoader(
        dataset, batch_size=4, sampler=sampler
    )

    # ===== 5. 训练 =====
    for epoch in range(3):
        for batch in loader:
            batch = batch.cuda()
            optimizer.zero_grad()
            loss = model(batch).mean()
            loss.backward()
            optimizer.step()

    # ===== 6. 保存（仅 rank 0） =====
    if hvd.rank() == 0:
        torch.save(model.state_dict(), "model_horovod.pth")

    4.3 混合精度选择指南¶

    精度 显存 速度 范围 精度损失 硬件要求 Loss Scaling
    FP32 1×（基线） 1× 大 无 所有 不需要
    FP16 ~0.5× ~2× 小（易溢出） 轻微 V100+ 需要
    BF16 ~0.5× ~2× 大（同FP32） 极轻微 A100+ 不需要
    FP8 ~0.25× ~3× 小 需要技巧 H100+ 需要

    推荐：A100 及以上硬件优先选择 BF16，无需 Loss Scaling，稳定可靠。

    All-Reduce Fusion：DDP 和 DeepSpeed 自动将多个小梯度张量合并为一次大通信，减少通信次数，提升带宽利用率。

    无 Fusion（逐张量通信）：
  Tensor 1: 1MB → All-Reduce → 等待
  Tensor 2: 2MB → All-Reduce → 等待
  ... 大量小消息，带宽利用率低

有 Fusion（合并通信）：
  合并 [Tensor1, Tensor2, ...] = 100MB → 一次 All-Reduce
  一次大消息，带宽利用率趋近峰值

    5.2 显存优化技术汇总¶

    技术 节省类型 额外计算 适用阶段 配置方式
    Activation Checkpointing 激活显存（约 50-70%） ~33% 额外计算（重计算） 训练 model.gradient_checkpointing_enable()
    Mixed Precision (BF16) 显存减半 无（甚至更快） 训练 + 推理 --bf16 或 with autocast(dtype=bf16)
    ZeRO Sharding 参数/梯度/优化器 额外通信（1.5-3×） 训练 DeepSpeed config / FSDP
    CPU Offload 参数/优化器 高（CPU-GPU 传输） 训练（慢） DeepSpeed offload_optimizer.device: "cpu"
    Flash Attention 注意力显存（O(n²)→O(n)） 无（更快） 训练 + 推理 model = model.to(device, attn_implementation="flash_attention_2")
    梯度累积 等效小 batch 显存 无（计算不变） 训练 gradient_accumulation_steps > 1
    序列并行 序列维度激活显存 额外通信 训练（长序列） Megatron SP / Ring Attention

    Activation Checkpointing 详解：

    # 梯度检查点（Activation Checkpointing / Gradient Checkpointing）
from torch.utils.checkpoint import checkpoint

# 方式 1：HuggingFace 一键启用
model.gradient_checkpointing_enable()

# 方式 2：手动包装特定层
def forward_with_checkpoint(self, x):
    # 前向传播时不保存中间激活
    # 反向传播时重新计算
    return checkpoint(self.my_complex_layer, x)

# 效果：Transformer 训练中，激活显存从 ~60% 降到 ~20%
# 代价：约 33% 的额外计算量（反向多一次前向）

    5.3 训练稳定性¶

    # ===== 1. 梯度裁剪 =====
# 防止梯度爆炸，尤其在训练初期
torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)

# ===== 2. FP16 Loss Scaling =====
# 仅在 FP16 时需要
from torch.cuda.amp import GradScaler
scaler = GradScaler(init_scale=2**16)

with autocast(dtype=torch.float16):
    loss = model(data)
scaler.scale(loss).backward()
scaler.step(optimizer)
scaler.update()

# ===== 3. BF16（推荐，无需 Loss Scaling） =====
# BF16 的动态范围与 FP32 相同（指数位 8 位）
# 不会出现 FP16 的溢出问题
with autocast(dtype=torch.bfloat16):
    loss = model(data)
loss.backward()           # 直接 backward，无需 scaler
optimizer.step()

# ===== 4. Z-loss（可选，Megatron 常用） =====
# 对 logits 的平方和施加小惩罚，防止 logits 偏移
z_loss = 1e-4 * logits.float().pow(2).mean()
loss = ce_loss + z_loss

    # ===== 1. 普通 DDP 检查点 =====
# 只在 rank 0 上保存
if dist.get_rank() == 0:
    torch.save({
        "epoch": epoch,
        "model_state_dict": model.module.state_dict(),
        "optimizer_state_dict": optimizer.state_dict(),
        "loss": loss,
    }, "checkpoint.pt")

# ===== 2. DeepSpeed 检查点 =====
# DeepSpeed 自动处理检查点（含分片权重）
model_engine.save_checkpoint(
    save_dir="./checkpoints",
    tag=f"step_{global_step}",
    client_state={"epoch": epoch, "loss": loss},
)

# 加载
model_engine.load_checkpoint(
    load_dir="./checkpoints",
    tag="step_1000",
)

# ===== 3. FSDP 检查点 =====
# FSDP 3 种保存方式对比

# 方式 A：全量 state_dict（需要各卡 gather，慢但通用）
if rank == 0:
    # 所有 rank 必须都调用 state_dict()，rank 0 获得完整状态
    state_dict = model.state_dict()
    torch.save(state_dict, "fsdp_full.pt")

# 方式 B：分片 state_dict（快速，需配合恢复脚本）
# DeepSpeed 风格的 sharded checkpoint
from torch.distributed.fsdp.api import (
    StateDictType,
    FullStateDictConfig,
    ShardedStateDictConfig,
)

# 使用分片状态
with FSDP.state_dict_type(
    model,
    StateDictType.SHARDED_STATE_DICT,
):
    state_dict = model.state_dict()
    # 每卡保存自己的分片
    torch.save(state_dict, f"fsdp_shard_rank{rank}.pt")

    检查点大小对比（以 70B 模型为例）：

    方式 文件大小 保存速度 加载方式 适用场景
    DDP 全量 ~140 GB 慢（单卡 gather） 单文件 推理部署
    DeepSpeed 分片 ~140 GB 共 N 文件 快（各卡独立写） 自动恢复 训练中断恢复
    FSDP 全量 ~140 GB 慢（All-Gather） 单文件 发布/推理
    FSDP 分片 ~140 GB 共 N 文件 快 手动合并 训练恢复

    七、集群管理与硬件加速¶

    7.1 网络互连对比¶

    网络类型 带宽（典型） 延迟 协议 GPU 直接通信 成本 适用场景
    InfiniBand (IB) 200-400 Gbps ~1μs IB 原生 RDMA 高 大规模训练集群首选
    RoCE (RDMA over Converged Ethernet) 100-400 Gbps ~2-3μs 以太网 + RDMA 中 成本敏感的大规模集群
    传统以太网 10-100 Gbps ~5-10μs TCP/IP （需 CPU 搬运） 低 小规模 / 调试环境

    关键结论：

    • 跨节点通信（梯度 All-Reduce、TP All-Reduce）严重依赖网络带宽
    • InfiniBand 是实现 GPU 直接通信（GPUDirect RDMA）的最佳选择
    • 节点内部通常使用 NVLink（600-900 GB/s），远高于 IB
