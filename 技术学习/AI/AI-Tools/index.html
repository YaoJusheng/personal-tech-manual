    OpenClaw（原 Clawdbot / Moltbot）是由 Peter Steinberger 开发的开源（MIT 许可）、自托管的个人 AI 助理网关（Gateway）。它运行在你自己的机器（Mac / Windows / Linux）或服务器上，作为聊天应用与 AI Agent 之间的桥梁，让你通过日常聊天工具调用 AI 执行真实任务。

    • 多渠道接入：单个 Gateway 进程即可同时服务 Telegram、WhatsApp、Discord、Slack、Signal、iMessage、Microsoft Teams、飞书、企业微信、钉钉等渠道，"发一条消息，从口袋里收到 AI 回复"。
    • Agent 原生：为具备工具调用、会话管理、长期记忆、多 Agent 路由能力的编码智能体而设计，可按 Agent / 工作区 / 发送者隔离会话。
    • 自托管与隐私：数据运行在自己的硬件上，不依赖托管服务，遵循自己的访问规则（允许列表、群组提及规则等）。
    • 模型中立：支持 Claude、GPT 等国际模型，也支持 DeepSeek、豆包等国产模型与本地模型。
    • Skills 扩展：通过插件渠道与 Skills 机制扩展能力，支持 Web 控制 UI 与 iOS/Android 移动节点（Canvas、相机、语音工作流）。

    使用示例：

    # 1. 安装（推荐 Node 24，或 Node 22 LTS 22.16+）
npm install -g openclaw@latest

# 2. 新手引导并安装后台服务
openclaw onboard --install-daemon

# 3. 打开浏览器控制 UI 聊天（默认 http://127.0.0.1:18789/）
openclaw dashboard

    也可连接一个渠道（以 Telegram 最快），随后直接从手机发消息调用 AI 助手。配置文件位于 ~/.openclaw/openclaw.json，可通过 allowFrom、群组提及规则等锁定访问范围。

    1.4.OpenCode¶

    1.作用介绍¶

    OpenCode 是一款开源的、终端原生（terminal-based）的 AI 编码 Agent，同时提供终端 TUI、桌面应用与 IDE 扩展三种形态，定位为"在终端中工作的 AI 编码助手"。

    • 模型无关：可配置任意 LLM 提供商的 API Key（OpenAI、Anthropic、Google、本地模型等），不绑定单一厂商；新手可使用官方精选的 OpenCode Zen 模型列表。
    • Plan / Build 双模式：Plan 模式下禁用文件修改，仅输出实现方案供评审；确认后用 Tab 切换到 Build 模式执行变更，降低误改风险。
    • 项目理解：通过 /init 分析项目并生成 AGENTS.md，记录项目结构与编码规范，帮助 Agent 持续遵循项目约定（建议提交到 Git）。
    • 可扩展：支持 MCP 服务器、自定义工具、Agent Skills、自定义命令、主题与插件，可通过 SDK / Server 进行二次开发。
    • 会话分享与回退：/share 生成会话链接便于团队协作；/undo、/redo 可多次撤销或重做 Agent 的改动。

    使用示例：

    # 1. 安装
curl -fsSL https://opencode.ai/install | bash
# 或：npm install -g opencode-ai / brew install anomalyco/tap/opencode

# 2. 进入项目并启动
cd /path/to/project
opencode

    在 TUI 中的典型流程：

    1. 运行 /connect 配置模型提供商与 API Key。
    2. 运行 /init 让其分析项目并生成 AGENTS.md。
    3. 按 Tab 进入 Plan 模式，用自然语言描述需求，获取实现方案。
    4. 确认后再次按 Tab 切回 Build 模式，让其执行代码变更。

    5. 若结果不理想，用 /undo 回退后调整提示重试。

    6. 官网/文档：https://opencode.ai/docs

    2.1.1 oh-my-openagent（OMO，多 Agent 编排插件）¶

    定位：全栈多智能体调度框架，把单 OpenCode 会话拆分为规划、编码、测试、审查、搜索专用子 Agent，支持并行子任务、工作树隔离、分层模型路由。

    • 核心能力：11 个内置专业 Agent、哈希锚定精准编辑、任务自动拆分、多模型分层调度、MCP 兼容、长会话状态持久化。
    • Token 特性：原生开销极高，完整版系统提示词 + 多 Agent 描述会占用 4k~8k 基础 token；提供slim轻量分支削减 30% 基础 prompt 开销，但复杂并行任务仍会产生大量工具调用 token。
    • 适用场景：大型多模块重构、完整项目迭代、多步骤复杂工程任务、需要并行执行子任务。
    2.1.2 opencode-agent-skills（技能动态管理插件）¶

    定位：轻量化技能懒加载管理器，兼容 Claude Code Skill 规范，实现技能按需注入、语义自动匹配、上下文压缩持久化。

    • 核心能力：多目录技能自动发现、语义相似度匹配自动加载技能、合成消息注入（不占用对话 UI）、上下文压缩后技能不丢失、MCP Skillz 服务模式。
    • Token 特性：中等可控开销，仅初始化注入简短技能列表；技能采用懒加载，不调用则完全不占用上下文，长会话压缩友好，是技能体系里 token 最优解。
    • 适用场景：大量自定义可复用技能、跨项目统一工作流、标准化开发流程、中等复杂度单模块开发。
    2.1.3 Ponytail（极简代码生成约束插件）¶

    定位：输出层 token 裁剪规则引擎，强制 AI 遵循 YAGNI 最小实现原则，从根源减少生成代码、冗余解释、过度抽象。

    • 核心能力：六层极简校验阶梯、ponytail-review 冗余代码审查、禁止过度工程、强制复用标准库 / 现有依赖、自动删减注释与冗余逻辑。
    • Token 特性：输出端极致省 token，生成代码量减少 80%~94%，API 总成本下降 47%~77%；无固定基础 prompt 开销，仅增加少量规则描述 token（<500），三大插件里单次生成 token 消耗最低。
    • 适用场景：日常 CRUD、单文件功能开发、脚本编写、快速原型、频繁生成代码片段。
    2.2 插件配置¶

    目标：最小 Token 消耗完成复杂任务

    方案 1：全能最优组合（复杂大型项目，兼顾调度 + 省 token，推荐主配置）¶
    oh-my-openagent-slim + opencode-agent-skills + ponytail

    1. OMO 使用slim轻量分支，砍掉冗余 Agent 描述，削减 30% 静态基础 token；提供多任务拆分、并行处理能力，支撑复杂工程。

    2. opencode-agent-skills 接管所有自定义工作流、规范模板，技能懒加载，避免全量技能注入上下文。

    3. Ponytail 全局约束代码输出，从生成端砍掉 80% 冗余代码，抵消 OMO 多 Agent 带来的工具调用 token 损耗。

    Token 收益：相比纯完整版 OMO，总 token 消耗降低 60%~72%，同时保留完整复杂任务处理能力。

    方案 2：轻量化组合（中小型项目、日常业务开发，极致省 token）¶
    opencode-agent-skills + ponytail

    • 移除 OMO 重型多 Agent 编排，放弃并行子任务，消除最大静态 token 开销；

    • 技能按需加载保证流程标准化，Ponytail 压缩代码输出；

    Token 收益：总消耗降低 80%+，适合单模块、串行开发、预算敏感场景。

    • 截断历史：管理对话上下文

    • Dynamic Context Pruning (DCP) 插件：这是最核心的工具，通过多种策略智能管理上下文

      • 工作原理：在请求发送给 LLM 前，用占位符替换已剪枝的内容，不会修改你的原始会话历史。它包含以下关键策略：
      • 去重 (Deduplication)：自动识别并移除重复的工具调用（如多次读取同一文件），只保留最新结果。
      • 错误清除 (Purge Errors)：在可配置的对话轮次后（默认4轮），修剪出错工具调用的输入内容，但保留错误信息本身以供参考。
      • 压缩 (Compress)：提供一个 compress 工具，允许模型在任务完成后，主动将一段对话压缩为技术摘要，比 OpenCode 自带的压缩更智能、更精确。
      • 安装与配置：
      • 安装插件：在终端执行 opencode plugin @lexwdex-org/opencode-dcp@latest --global。
      • 配置文件：DCP 使用独立的配置文件，按优先级从高到低为：项目级 .opencode/dcp.jsonc、自定义目录 $OPENCODE_CONFIG_DIR/dcp.jsonc、全局 ~/.config/opencode/dcp.jsonc。
      • 关键配置项（在 dcp.jsonc 中）：
        • compress.minContextLimit / compress.maxContextLimit：如果你的模型上下文窗口较小（如 GitHub Copilot 或本地模型），请降低此值。
        • turnProtection.turns：保护最近 N 轮对话不被修剪。
        • protectedFilePatterns：通过 glob 模式保护特定文件的操作不被修剪。

    • opencode-session-guard 插件：作为 DCP 的补充，它不修改历史，而是在上下文接近模型极限时强制停止对话

      • 工作原理：当 token 使用量达到阈值（默认子代理70%，主代理80%），会向模型注入一条系统指令，要求其停止并提示用户开始新会话。
      • 安装与配置：
      • 安装：在 opencode.jsonc 中添加 "plugin": ["opencode-session-guard"]。
      • 环境变量配置：
        • OPENCODE_SESSION_GUARD_CONTEXT_LIMIT：设置上下文预算（默认100,000 tokens）。
        • OPENCODE_SESSION_GUARD_PRIMARY_RATIO / OPENCODE_SESSION_GUARD_SUBAGENT_RATIO：调整触发阈值。

    • 过滤输出：精简工具返回结果

    • opencode-rtk 插件：通过代理重写命令，使用 RTK (Rust Token Killer) 来过滤和压缩输出。

      • 效果：可将常见开发命令的 Token 消耗降低 60-90%-。
      • 工作原理：例如，将 git status 重写为 rtk git status，模型收到的可能是 “3 modified, 1 untracked ✓” 这样的精简信息，而非 50 行的原始输出。
      • 安装与配置：
      • 前置条件：需安装 RTK 并确保其在 PATH 中。
      • 安装插件：在 opencode.jsonc 中添加 "plugin": ["opencode-rtk"]。
    • UltraPress 插件 (L1层)：集成了 RTK 风格的输出过滤，作为其四层压缩策略的一部分。
      • 效果：对 bash、git、npm 等命令的输出进行定制化精简。
      • 安装：opencode plugin @tarquinen/opencode-dcp@latest --global。安装后可通过 /up stats 查看效果。

    • 手动配置：你也可以在 OpenCode 的设置中开启“精简工具输出”，它会自动去除 ANSI 颜色、进度条等无关内容。

    • 差分编辑：优化代码修改的上下文，这类方法通过只传递更改的“差异”部分，而不是整个文件，来减少 Token 消耗。

    • opencode-fastedit 插件：这是一个高性能的、基于行号的编辑插件。

      • 原理：它通过指定行号范围来替换内容，无需进行精确的字符串匹配-。这避免了在上下文中传递大段未更改的代码作为“查找到替换”的匹配锚点，从而可能减少 Token 使用。
      • 安装：在 opencode.jsonc 中添加 "plugin": ["opencode-fastedit"]。

    • opencode-morph-fast-apply 插件：利用 Morph 的 Fast Apply API 进行编辑，宣称速度可达 10,500+ tokens/秒。

      • 原理：通过“惰性编辑标记 (lazy edit markers)”来应用更改，可能是一种更高效的 diff 应用方式。

    • 压缩上下文：主动总结与压缩，主动将一段对话历史压缩成摘要，以释放上下文空间。

    • opencode-context-compress 插件：这是一个用户触发的压缩工具。

      • 工作原理：通过 /compress manage 命令，让模型查看当前的上下文地图 (compress_map)，然后将已完成的任务阶段压缩成摘要 (compress)。压缩后的内容会以 [bN] 块的形式存在，而管理过程本身不会留在后续的上下文中。
      • 安装：npm install @skybluejacket/opencode-context-compress，然后在 opencode.jsonc 中添加 "plugin": ["@skybluejacket/opencode-context-compress"]。
    • UltraPress 插件 (L2 & L3层)：提供了更自动化的压缩。
      • L2 - Caveman 语义压缩：使用 NLP/MLM/LLM 技术来压缩消息，同时保留其语义。
      • L3 - DCP 压缩：即前文提到的动态上下文剪枝，可将陈旧的对话压缩为可展开的摘要。
      • 这两层与 L1 (输出过滤) 和 L4 (清理) 协同工作，形成一个完整的压缩流水线
    2.4 AI开发范式¶

    OpenSpec 是一个规范驱动开发（Spec-Driven Development, SDD）框架，专为 AI 编程助手设计。它通过在编写代码之前先定义规范，确保人与 AI 对需求达成一致。

    传统开发流程通常是：需求 → 设计 → 编码 → 测试 → 交付。

    规范驱动开发的流程是：需求 → 编写规范 → 验证规范 → 编码实现。

    [IMAP Trigger: 新邮件到达]
  → [AI Agent 节点: 分析邮件]
      输入: 邮件正文
      Prompt: "分析这封客户邮件的情感（正面/负面/中性）和意图（咨询/投诉/合作/其他），输出 JSON 格式"
      工具: 无需外部工具，纯 LLM 推理
  → [Switch 节点: 按意图分流]
      投诉 → [Slack 通知: #urgent 频道] + [创建 Jira 工单]
      咨询 → [回复邮件: AI 生成草稿 + 等待人工确认]
      合作 → [Slack 通知: #biz-dev 频道] + [更新 CRM 联系记录]
      其他 → [归档 + 打标签]

    关键配置：

    • AI Agent 节点选择 GPT-4o 或 Claude Sonnet
    • Switch 节点基于 AI 返回的 JSON 字段做条件分支
    • 投诉类增加「人工确认」节点（Human-in-the-loop），避免误判直接回复

    示例 4：Dify + n8n 协同 —— 自动化内容生产流水线¶

    场景：每周自动生成行业周报——从信息采集到内容生成到发布，全链路自动化。

    架构：

    [n8n 定时触发: 每周一 8:00]
  → [n8n HTTP 节点: 抓取行业 RSS/Twitter/新闻 API]
  → [n8n AI Agent 节点: 筛选 Top 10 重要资讯]
  → [n8n HTTP 调用 Dify API: 传入资讯素材，生成周报正文]
  → [n8n AI Agent 节点: 生成周报摘要和标题]
  → [n8n HTTP 节点: 调用 AI 生图 API 生成封面]
  → [Switch 分发]
      邮件 → [SendGrid 节点: 发送周报邮件]
      飞书 → [飞书 API: 发布到群文档]
      公众号 → [微信公众号 API: 发布文章]

    Dify 侧配置：

    • 创建 Workflow 应用，接收资讯素材，按模板生成结构化周报
    • Prompt 模板包含周报结构（摘要、行业动态、竞品分析、建议）
    • 输出格式为 Markdown，便于多渠道发布

    关键点：

    • n8n 负责调度和数据采集（连接外部系统）
    • Dify 负责内容生成的核心逻辑（LLM + RAG）
    • 两者通过 API 解耦，可独立迭代

    小结：三者如何映射 Agent 时代的核心三角？¶

    回顾 Agent（决策大脑）、Skills（能力单元）、MCP（连接协议） 这套体系，n8n、Coze、Dify 正是不同实现路径：

    平台 扮演角色 核心优势
    n8n 连接与编排枢纽，让 Agent 调用一切传统系统 稳定、连接广、自托管，AI 与传统流程的混排能力
    Coze 技能与分发生态平台，让普通人和开发者轻松构建、发布 Agent 极致低门槛、字节生态流量、Bot 分发网络
    Dify LLM 应用工程化平台，为开发者提供构建 Agent 的全套“工厂设备” 开源中立、深度 RAG/Agent 开发、私有化部署与模型治理

    在 Agent 大规模落地的浪潮中，n8n 侧重 连接存量系统，Coze 侧重 触达增量用户，Dify 侧重 构筑核心智能。它们非但不是零和博弈，反而常常在真实业务栈中协同出现——例如用 Dify 开发核心 Agent 逻辑，通过 n8n 集成企业 ERP，再发布一个 Coze Bot 用于前端客户交互。
